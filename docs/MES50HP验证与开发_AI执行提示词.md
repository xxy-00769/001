# MES50HP 旧工程验证、整合与开发提示词

日期：2026-10-19。适用硬件：MES50HP／PGL50H；最终协同设备为香橙派 5 16GB／RK3588S。

## 1. 先确定连接方案

现在不要求香橙派必须在场，但从网络开发阶段起必须有电脑或香橙派作为测试接收端。不能只开发 FPGA 发送逻辑，最后才第一次检查能否接收图片。

开发阶段可以这样连接：

```text
开发电脑 ──配套下载器/JTAG── MES50HP       编译结果下载与调试
开发电脑 ──对应的串口连接── MES50HP         日志和控制，按板卡实际接口确认
摄像头 ──匹配排线──────── MES50HP          摄像头输入
外部视频源 ──HDMI──────── MES50HP HDMI-IN  视频输入
MES50HP HDMI-OUT ──HDMI── 显示器           可选板级调试显示
MES50HP RJ45 ──网线────── 开发电脑 RJ45    视频收发与协议验证
```

最终连接：

```text
MES50HP RJ45 ──Cat5e 或 Cat6 网线── 香橙派 5 RJ45
香橙派 HDMI ──HDMI 线───────────── 显示器
```

需要同时连接电脑、外部图像源或多块板时，使用千兆交换机。直连先使用普通网线；确认双方实际协商到千兆，若协商异常再检查 PHY 配置、线缆和接口状态。设置固定地址时选择未被占用的同一网段，不能照抄一个可能冲突的地址。

JTAG 用于下载调试，UART 用于低速日志/命令，HDMI 用于图像输入输出；它们都不替代本项目首版 FPGA—香橙派网络数据链路。网口图像协议是待验证/开发功能，不是插线后就有的视频设备。普通 HDMI 线不能接入香橙派 HDMI 输出口来接收 FPGA 画面；也不能默认用一根 USB 线得到视频传输功能。

当前先采用千兆以太网 UDP，PCIe、光口、USB 视频作为后续有明确需求时的备选。先测出实际带宽瓶颈再决定是否换接口。四路原尺寸高清视频不预设能通过千兆链路传输。

## 2. 固定的职责范围

FPGA：时钟复位、摄像头/HDMI/网络图像接收、通道与帧编号、DDR 完整帧缓存、格式转换、裁剪缩小、可开关的滤波/灰度/边缘特征、图像传输、按键事件、LED 控制、运行统计和故障恢复。

香橙派：视频文件解码、模型输入适配、车道检测与拟合、虚实线判断、斑马线/道路边缘/可行驶区域检测、信号灯和目标识别、多帧跟踪、交通规则判断、全景标定融合、最终界面和 HDMI 输出。

保留彩色主图像；灰度、滤波和边缘图作为可选辅助路径。避免强制滤波、缩小或丢失颜色影响模型识别。最终检测框由香橙派绘制，不要求回传 FPGA 画框。FPGA HDMI 是调试路径。

## 3. 功能清单与开发顺序

| 编号 | 功能 | 验证重点 | 优先级 |
|---|---|---|---|
| F01 | 工程与硬件基线 | 器件、工具/IP 版本、顶层、引脚、时钟、源码可重建 | 首先 |
| F02 | 时钟、复位、启动顺序 | PLL、各域复位、DDR 与接口就绪后再启动 | 首先 |
| F03 | LED、按键、串口状态 | 消抖、事件、可读取状态；按实际外设数量映射 | 基础 |
| F04 | DDR 基础读写 | 地址与数据模式测试、错误统计 | 基础 |
| F05 | HDMI 彩条/单路调试输出 | 显示时序、颜色、稳定性 | 基础 |
| F06 | 一路摄像头采集 | 配置、像素拼接、颜色、行帧边界 | 基础 |
| F07 | 一路完整帧缓存 | 写完发布、读完释放、无覆盖/撕裂 | 基础 |
| F08 | HDMI 输入 | 固定支持规格、断开恢复、独立时钟 | 基础 |
| F09 | 内部图像接口 | 通道、帧号、格式、尺寸、采集计数、帧完整性 | 单路稳定前确定 |
| F10 | 格式整理、裁剪、缩小 | 边界、颜色、坐标映射、与参考输出对比 | 第一阶段处理 |
| F11 | 网络控制和测试数据 | ARP、UDP、计数器、命令与应答、心跳 | 提前与接收端联调 |
| F12 | 测试图片/真实视频发送 | 分包、完整性、速率控制、重启恢复 | 单路闭环 |
| F13 | 灰度、简单滤波、Sobel | 独立开关、像素和标志对齐、资源/时序 | 单路闭环后 |
| F14 | 双目并行 | 不是二选一；独立接收、缓存、帧号 | 双路阶段 |
| F15 | 摄像头与 HDMI 并行 | 不同输入时钟、规格、带宽与调度 | 三路阶段 |
| F16 | 网络图像输入与回传 | 组帧、校验、超时、完整后处理、双向负载 | 第四路候选 |
| F17 | 四路并行 | 独立动态来源、断一路不干扰其他路 | 多路阶段 |
| F18 | 统计、恢复、固化、持续运行 | 贯穿各阶段；最后形成完整交付记录 | 全程 |

先单路正确，再多路；先测试图，再真实图；先固定规格，再增加兼容规格。F09、F18 需要在早期就落实，不是最后才补。F08 与摄像头可分别验证，F11 可在单路图像稳定前开始独立验证。

## 4. 提示词使用方法

把旧工程、板卡手册、对应例程放到另一台电脑能访问的位置。在工程根目录打开 AI，先发送提示词 0，再按阶段发送后续提示词。已有功能也要验证，不预设必须重写。

每个阶段可以持续多轮。当前阶段达到验收条件或产生明确阻塞记录后，再进入依赖它的下一阶段。独立任务不必等阻塞解除才能推进。没有实物时允许做静态检查、仿真和接收程序开发，但上板结果必须标为待验证。

以下路径均是拟建立的项目相对路径，用于在另一台电脑组织记录，不代表该电脑已经存在这些文件。

## 提示词 0：固定分工与工作约束（首先发送）

```text
你现在接手我已有的 MES50HP FPGA 工程。当前打开目录是工作入口，请先识别实际工程位置、顶层和资料路径，不假设特定路径存在。

目标硬件为 MES50HP/PGL50H，后续协同设备为香橙派5 16GB/RK3588S。先以硬件手册、原理图、工程实际约束核对具体器件封装和板卡版本。

职责固定如下：
1. FPGA负责采集、DDR缓存、格式整理、裁剪缩小、可选灰度/滤波/边缘特征、网络图像收发、按键与LED、统计和故障恢复。
2. 香橙派负责车道与虚实线、斑马线、道路边缘、信号灯、行人车辆等最终识别，多帧处理、驾驶判断、全景融合、界面和最终HDMI输出。
3. FPGA保留彩色主图；基础特征是可选辅助路径。FPGA HDMI仅作调试。
4. 首版采用千兆以太网UDP协同，先用电脑作测试端，后迁移到香橙派。不预设现有网口例程已支持图片收发，不预设PCIe DMA可用。
5. 单板先单路，再双目并行，再摄像头+HDMI，再验证网络第四路。第二块FPGA不是默认项。

请遵守：
- 先检查项目内适用的AGENTS.md等工作约束，再审查工程。
- 第一轮只审查和记录，不批量重构、升级IP、改引脚或删除旧文件。文档可以新增。
- 记录当前Git状态；有Git时保留未提交改动，没有Git时制定版本备份方案。不要清理旧工程产物来制造干净状态。
- 旧工程作为证据保留，按模块决定保留/修复/替换，不能因为结构不同就全部推倒。
- 引脚、电压、时钟、DDR和PHY设置以对应实物资料为准，禁止猜测。
- 区分“源码存在、静态检查通过、仿真通过、综合通过、布局布线时序通过、上板通过”。禁止把其中一步写成全部完成。
- 工具或硬件不可用时记录限制，继续可独立完成的工作，不编造报告。
- 每次只推进当前阶段，完成修改、适当检查和文档，再报告结果。
- 阶段结束给出：改动文件、实际执行检查、证据路径、未验证项、下一步。

现在先读取目录并给出工程概况，不进行RTL改动。
```

## 提示词 1：审查旧工程，找出能复用的部分

```text
请审查当前旧工程，完成F01及其他功能的现状清点，不修改RTL和约束。

1. 找出所有PDS工程、顶层、源码、约束、IP配置、初始化文件、脚本和生成产物，辨别当前主工程、旧副本和自动生成文件。
2. 确认顶层实际引用的模块。不能仅按文件存在就判定功能已接入。
3. 追踪时钟复位、摄像头、HDMI、DDR、网络、按键LED、串口链路；画出真实数据流，用文件位置支持结论。
4. 特别检查摄像头是单路选择还是双路同时采集；HDMI是切换输入还是并行；网口是发送测试数据、字符还是完整图像。
5. 检查已有日志与下载文件对应哪个源码版本，不把旧报告当作当前检查结果。
6. 按F01-F18建立功能矩阵：现状、证据、缺口、保留/修复/替换建议、下一项验证。
7. 检查PDS和仿真工具能否调用、IP是否齐全，列出缺失外部文件和绝对路径依赖。不执行来源不明安装包。

生成docs/fpga_audit.md、docs/fpga_function_matrix.csv、docs/fpga_validation_plan.md。输出以具体证据为依据，给出最小改动路线。本轮结束不要开始大规模整合。
```

## 提示词 2：复现旧工程的可用基线

```text
基于审查记录，先复现当前最可信的已有工程，作为后续比较基线。

确认版本备份和可恢复点，补齐已知依赖，使用匹配PDS/IP版本尝试重建。不要为追求最新版本自动升级IP。

分别记录综合、布局布线、资源、时序、未约束路径和警告。工具可运行时真正执行；工具不可用时只记录静态发现和人工执行步骤。

核对器件、引脚、电气标准、输入时钟、复位、DDR初始化、PHY延时等设置。缺少硬件证据时列出待核对项，不猜配置。

有板卡和下载能力时验证当前版本；无板卡时编写最短上板操作表。准备LED/按键/串口状态及DDR基础验证。未知的旧下载文件不得直接视为可用于当前硬件。

生成docs/baseline_reproduction.md，明确当前能可靠复现到哪一级。先修复阻止基线重建的问题，保持改动最小，不直接合入四路功能。
```

## 提示词 3：建立一路图像正确性基线

```text
请在可恢复基线上完成一路视频基线。优先复用旧工程已经可靠运行的输入，不同时改多个输入模块。

检查一路摄像头的配置、字节拼像素、RGB565位序、行帧边界、实际尺寸和时钟；核对DDR缓存读写完成条件、槽状态和复位恢复。

加入必要的输入帧数、完整帧数、丢帧、缓存溢出及视频有效状态。接口、计数器命名尽量沿用一致规范。

用纯色、网格、递增数据验证颜色、位置和完整性。能仿真时针对边界、缺帧、输入输出速度不同等风险做小范围有意义的验证；不写仅重复实现的形式测试。

通过HDMI调试输出验证一路画面。单独说明输入规格和显示规格，不能假定所有720p/1080p例程参数相同。

验收：完整图像无明显错行和撕裂，计数器解释得通，断流后恢复。无实物则保留上板待验证状态。输出docs/single_stream_validation.md，并更新功能矩阵。
```

## 提示词 4：确定内部图像接口并实现基础处理

```text
基于已验证单路，整合统一图像接口和可配置基础处理，避免一次重写全部工程。

先形成docs/video_interface.md：明确像素格式、有效信号、帧/行标记、通道号、帧号、尺寸、采集计数、背压规则、跨时钟方式及缓存所有权。摄像头/HDMI不能等待时，定义溢出后的整帧丢弃与重新对齐。

依次实现/复用：颜色格式整理、ROI裁剪、缩小。首版可用最近邻缩小验证链路，但记录对细线、小目标识别的影响。保留彩色主路径；配置在安全帧边界生效，记录实际裁剪和缩放关系。

主路径稳定后，才加入独立开关的灰度、一种简单滤波、Sobel。特征图必须与来源帧、尺寸及坐标关系对应，像素和有效标志延迟一致。

建立软件参考，检查纯色、网格、边界和选定真实图。记录整数结果或近似误差。每新增模块查看资源和时序，不一次加入所有增强算法。

不要在本阶段开发车道语义识别或驾驶规则。输出docs/preprocess_validation.md并更新矩阵；未完成的可选模块明确留待后续。
```

## 提示词 5：网络控制与电脑测试工具

```text
请为MES50HP与电脑建立首版以太网UDP测试链路，之后同一协议迁移至香橙派。

先核对实际板上PHY、RGMII时钟/延时和已有ARP/UDP模块，不能套用其他网口扩展板工程。确认MAC/IP配置、链路状态和实际协商速率。

第一步FPGA发送递增数字；第二步电脑发送带编号的设置LED或查询状态命令。配置/命令定义应答、超时及去重，避免重发变成重复翻转。

先写docs/network_protocol.md，明确网络字节序、消息类型、长度、版本、会话/重启识别和边界检查，再实现收发。

开发tools/host_test下的最小测试工具，优先使用Python标准库提供命令收发和日志；不要让基础网络测试必须依赖识别模型。固定地址按当前网卡环境配置，避免与现有网络冲突。

能接硬件时实测双向通信和重启恢复；否则用模拟数据验证电脑端并列出待上板步骤。输出docs/network_control_validation.md。
```

## 提示词 6：测试图片与真实视频传输

```text
基于控制链路，先传固定彩条/棋盘格，再传一路真实图像。先固定低负载规格，实测后再提高。

发送协议明确会话、通道、帧号、图像格式/尺寸、帧字节数、片号/片数、偏移、有效长度及完整性检查。按实际MTU限制单包大小，首版避免IP分片，不假设全链路支持巨帧。

电脑工具应支持重组、图片保存、可选预览、统计和模拟数据测试。允许包乱序、重复；缺包或超时不得提交拼错的帧，队列有上限，优先保留新的完整图。预览依赖可作为可选安装项。

测试图逐字节比对，真实图检查颜色和位置；记录发送/接收完整帧数、字节率、丢包/丢帧、队列积压、重启和断线恢复。无时钟校准不能直接用两台设备时间相减宣称单向延迟。

执行适当编译/仿真/上板验证，明确证据等级。输出docs/video_transport_validation.md及可复现运行命令。网络接收成功后再与香橙派联调，不必等待所有四路完成。
```

## 提示词 7：双目真正并行，再增加 HDMI

```text
从稳定单路扩展双路，再增加HDMI。先审查原有结构，不能把输入选择器当成并行采集器。

每个摄像头保留独立接收、时钟处理、边界识别、缓存和帧号，公用DDR和网络时明确仲裁与速率限制。相机配置总线是否可共享、地址和选择线如何工作，必须核对硬件，不能猜。

双路稳定后加入HDMI独立输入。保留各路实际规格，先采用明确支持组合，不立即实现任意分辨率热切换。

计算新增逻辑、片内存储、DDR读写量和网络负载，执行资源/时序检查。不得靠无限增加FIFO解决长期吞吐不足。

逐路展示不同动态内容、遮挡/断开一路，验证其他路持续更新；记录各路采集、发送和完整接收帧率。没有上板证据时不能标记并行采集完成。

输出docs/multi_input_validation.md并更新功能矩阵。两路和三路分别保存可恢复版本，不跳过中间验收。
```

## 提示词 8：网络图像输入、第四路与双向负载

```text
请新增网络像素图像输入，支持外部设备/香橙派解码后的图片进入FPGA，处理后返回。这是图像数据入口，不是字符叠加或原始MP4文件接收。

沿用协议定义或明确版本扩展，实现长度/偏移/通道/格式边界检查、完整性、组帧、超时丢弃、缓存上限、重复包处理、会话变化清理。只有完整有效帧可以提交处理。

电脑端发送独立动态测试图。确认返回数据确实经过FPGA预处理，不是电脑/香橙派本地直接显示。定义输入与输出消息类型和路由，避免自动回送循环。

先验证单一网络输入往返，再与双目和HDMI并行。分别核算FPGA、接收设备的RX/TX、DDR及全部网络负载。处理能力不足时明确降低尺寸/帧率，不隐性丢图后宣称达标。

四路验收使用独立动态编号，逐路断开和改变内容；第四路是独立来源，不能重复已有画面。四路同步采集不等于四路同步曝光，也不等于全景融合。

输出docs/network_input_validation.md和docs/four_stream_validation.md。四路640x360 RGB565每路15fps仅作首测建议，最终规格以实测确定。
```
