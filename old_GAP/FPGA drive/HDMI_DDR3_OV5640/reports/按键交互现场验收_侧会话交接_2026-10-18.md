## 二、硬件与按键映射

用户明确确认：实物为 MES50HP 底板，带 8 个用户按键。
当前只使用 KEY1 至 KEY4，KEY5 至 KEY8 暂不使用。

以下引脚与电气信息来自继承的手册核对记录，本侧会话未重新作电气测量。

| 按键 | 记录中的 FPGA 引脚 | 用途 |
| --- | --- | --- |
| KEY1 | K18 | 左侧变道请求 |
| KEY2 | L15 | 右侧变道请求 |
| KEY3 | J17 | 对已选择方向提出强制请求 |
| KEY4 | K16 | 取消当前请求及告警 |

记录中的输入条件为按下低电平、LVCMOS33、3.3 V。
重新加载键 REST/RSTN 不是 KEY4，不能用重新加载程序代替取消请求。

## 三、运行模式与数据流

现场照片右上角明确显示 `RULE TEST`。
按既有设计，该模式的数据关系为：

```text
CMOS1 摄像头 -> 现有 FPGA 图像处理 -> DDR 视频缓存 -> HDMI 背景

合成虚实线场景 -> 规则状态机 <- KEY1/KEY2/KEY3/KEY4
                         |
                         +-> 右上角文字、请求方向箭头及告警边框
```

右上角的规则输入是合成测试状态，不是从背景道路图像识别出的虚实线。
左上角原候选检测 HUD 与右上角 RULE TEST 是不同来源，不能混读。
背景中的绿色或青色候选叠色也不代表已经完成道路语义识别。

## 四、各状态的准确含义

| 屏幕状态 | 含义 | 注意事项 |
| --- | --- | --- |
| STRAIGHT / REQ:- | 当前没有有效方向请求 | 是交互状态，不是已经判断车辆可以安全直行。 |
| UNKNOWN | 合成规则无效或未知 | 撤销方向请求与告警，不能强行输出驾驶结论。 |
| DASHED REQ / REQ:L 或 R | 请求侧为虚线，显示该侧请求 | 黄色箭头表示请求，不表示变道安全。 |
| BLOCKED / REQ:L 或 R | 请求侧为实线，规则阻止请求 | 即使有方向箭头，也不表示允许执行变道。 |
| SOLID ALARM | 已有实线侧请求，又收到强制请求 | 预期红色告警文字及红框，不控制真实车辆。 |

程序没有名为 `UNLOCKED` 的状态。
用户之前所说的“unlocked”应与实际屏幕的 `BLOCKED` 区分。

### KEY3 为什么可能没有明显变化

KEY3 不是独立页面切换键。先要存在方向请求，而且该侧为实线。
单独按 KEY3、对虚线侧按 KEY3、在 UNKNOWN 时按，或等请求超时后再按，
均不能据“没有出现告警文字”判断按键损坏。

### KEY4 为什么没有专用文字

KEY4 是取消操作，没有单独的“KEY4”提示页。
有请求时按下，正常有效规则下应恢复 `STRAIGHT`、`REQ:-`。
若本来已经是 STRAIGHT，按下自然可能没有明显变化；
未知规则下则保持或返回 UNKNOWN。

历史设计记录中，请求约 2 秒自动撤销、规则场景每 120 个显示帧轮换。
这些是配置估算，不是本次现场测量，因此观察时大多出现 STRAIGHT/UNKNOWN 并不矛盾。

## 六、纠正旧状态，避免重复开发

继承记录曾显示：一次独立构建在布局布线时发生主机内存分配失败，尚无位流。
那是当时的构建历史，不是当前板卡状态。

最新照片已经证明，现场存在正在运行的 RULE TEST 按键交互程序。
因此，不能继续直接回复用户“按键还没有烧进板卡”。
同时，照片不能单独证明它来自哪次构建，也不能补造后续 PNR 成功、
时序通过、位流哈希、下载成功日志或 Flash 写入记录。

正确处理方式：

1. 保留旧失败日志，不覆盖历史证据。
2. 使用主会话已有构建与下载记录核对当前程序身份。
3. 将本次照片及用户反馈单独登记为新增实机证据。
4. 相同代码、相同配置已有合格结果时，不重复全量仿真、综合和映射。
5. 不为增加按钮文字提示就直接重构或重烧；是否需要改善提示另行决定。

## 七、验收边界与后续范围

本次可以确认的是：用户现场反馈，本地 RULE TEST 按键交互测试通过。

本次不能确认：

- 摄像头道路区域、车道线虚实、行人、障碍物或交通灯识别准确率。
- FPGA 与 ARM 真实图像传输、返回结果及超时处理闭环。
- 四路并行视频、端到端帧率与延迟、完整外部接口时序或长期可靠性。
- 比赛所有功能完成、车辆安全控制能力或量产能力。

当前先完成按键阶段的程序身份核对与证据归档，再由主会话按用户既定路线
选择下一个单一功能。不要因历史内存失败忽略新增现场结果，
也不要因按键测试通过直接宣布真实识别完成。
