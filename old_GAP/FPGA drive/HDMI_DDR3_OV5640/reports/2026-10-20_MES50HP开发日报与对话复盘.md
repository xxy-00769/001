## 1. 当前结论

项目沿用原 MES50HP 工程开发，没有从零重写。

截至当前对话结束，最近已交付 **V4：KEY8 六档视频模式切换**：

```text
原图 -> 灰度 -> 3x3 中值滤波 -> Sobel
     -> 白黄颜色候选 -> 旧车道/斑马线诊断 -> 原图
```

- 上电默认原图，原图不叠加候选涂色或 HUD。
- KEY8 消抖后一次按下推进一档，长按不自动重复，稳定释放后才允许下一次。
- 模式在缓冲后的视频帧边界锁存，HUD 开关在对应延迟后的帧边界对齐。
- 已通过针对性 RTL 仿真、完整 PDS 构建和现有约束下的布局布线后时序检查。
- 已生成本轮命名 SBIT，交给用户手动烧录。
- **当前对话尚无 V4 烧录后的现场反馈，不能写成 V4 已上板通过。**

FPGA 全部规划功能并未完成。裁剪缩小、实体千兆网图像传输、完整配置/状态链路、双目并行、HDMI 输入和网络第四路仍需继续开发或验收。

## 3. 本对话固定下来的职责与约束

### 3.1 FPGA 与香橙派分工

| 范围 | FPGA：MES50HP | 香橙派 5 |
| --- | --- | --- |
| 摄像头、HDMI、网络图像输入 | 接口接收、格式整理、完整性与断流检查 | 文件模式解码并发送待处理图像 |
| 帧管理 | 通道号、帧号、采集时间、DDR 缓存及所有权 | 接收队列、跨路对应及识别队列 |
| 基础图像处理 | 裁剪缩小、可选灰度、滤波、Sobel、颜色/亮度候选 | 模型所需最终尺寸适配、归一化 |
| 道路理解 | 提供彩色主图和可选特征 | 最终车道、曲线、虚实线、斑马线、道路边缘及可行驶区域判断 |
| 目标识别 | 保留可用彩色图像 | 信号灯、行人、车辆、障碍物识别与跟踪 |
| 驾驶判断 | 上报按键、执行 LED 命令 | 规则、多帧稳定、风险与驾驶提醒 |
| 多路全景 | 提供独立图像与时间信息 | 标定、对齐、变换、融合 |
| HDMI 显示 | 可选调试显示 | 正式界面、检测框、文字和最终 HDMI |

彩色主图不能被唯一的灰度图或边缘图取代。旧 FPGA 检测、线型启发式和 HUD 可以保留为诊断，但不能据此继续默认扩大“FPGA 最终理解道路并完成驾驶判断”的正式架构。

### 3.2 开发方式

1. 基于原工程按模块保留、修复、复用，不因结构不同而全部推倒。
2. 首版协同采用千兆以太网 UDP，先用电脑，后迁移香橙派；不默认旧编码已形成实体链路，也不默认 PCIe DMA 可用。
3. 输入扩展顺序为单路、双目并行、摄像头加 HDMI、再验证网络第四路；第二块 FPGA 不是默认方案。
4. 用户后来明确采用“代理修改代码、做针对性检查并编译；用户手动烧录、上板反馈；代理修复问题”的协作方式。
5. 不反复开展全工程审查、全量备份、验证全部旧代码；只做当前功能真正依赖的检查。
6. 实物身份待确认项继续保留，但只阻止依赖具体参数的操作，不再作为所有独立 RTL 开发的全局门槛。
7. 不升级 IP、不猜引脚电压、不恢复 v12 实验、不删除档案；源码、仿真、综合、时序、上板必须分级表述。

上述是对话中逐步确定的开发规则；早期 S1/S2 的临时阶段限制不能覆盖后来明确授权的修复和构建。本次用户只要求整理文档，本文中的后续建议也不是自动开工授权。

## 5. 各阶段实际完成了什么

### 5.1 审查与 S1 准备

已有审查产物覆盖旧工程真实连接、目标架构、功能矩阵和执行计划。

历史检查的重要结论包括：

- 主顶层是选用 CMOS1 的单路采集，不是两路同时采集。
- 原 RGB565 转换、DDR、HDMI 和基础处理/旧车道诊断源码具有复用价值。
- v11 四键交互的特定历史上板结论只属于归档版本，规则曾使用合成状态；摄像头背景不使其成为真实感知规则。

- `road_*` 卷积/整网推理和 PC SegFormer 属研究支线；软件速度、距离、TTC 不能当实测值。
- 测试台、CRC、超时、坏帧清除等资产不能当冗余文件随意删除。

### 5.7 V4：KEY8 六档显示

| 模式 | 输出与边界 |
| --- | --- |
| 0 原图 | 缓冲后原始彩色，不涂候选、不画 HUD |
| 1 灰度 | RGB 亮度转换，重新打包为 RGB565 |
| 2 滤波 | 3x3 灰度中值滤波；不是彩色去噪，也不是本轮新增高斯滤波 |
| 3 Sobel | 横纵梯度绝对值之和，饱和到 8 位亮度后显示 |
| 4 颜色候选 | 道路 ROI 内原有白/黄候选与支持筛选；白候选画绿、黄候选画青，无 HUD |
| 5 旧诊断 | 恢复原有候选、车道几何/HUD、斑马线诊断显示；不是新训练的最终识别系统 |

KEY8 依据已有对应 MES50HP 手册及归档硬件核对记录接入 H17、低有效、LVCMOS33/3.3V；没有凭板名猜引脚，没有把旧单键例程当作全部八键的现场测量。

控制与对齐实现：

- 50 MHz 参考域使用 1000000 周期消抖，配置意义为 20 ms。
- 采用六态 Gray 环及两级同步跨入视频时钟域。
- 使用 `syn_encoding = "original"` 保留实际源寄存器编码。
- 图像处理在自己的缓冲后帧标记锁存模式，不能直接用原始 VS 改变正在冲刷的上一帧尾行。
- 诊断输出的 RGB、DE、VS、帧号和采集时间一起接入 DDR。
- 图像帧边界之间若发生极快的多次切换请求，显示可能只呈现最新请求；常规逐次按键验收应留出看清一帧的时间。

**需要明确的架构折中：** V4 为复用现有 DDR/HDMI，单一显示缓存存储当前选择的画面。模式 1～5 下，里面不是同时保留的干净彩色帧。独立 clean RGB/DE/VS 及标签仍保留在 RTL 接口，未新增独立外部彩色出口或第二套缓存，未使用信号可能被综合裁除。今后图像传输应明确接 clean 分支或独立管理彩色缓存，不能无条件把“当前显示 DDR”当永久彩色主图。

## 9. 用户疑问与开发偏差复盘

### 9.1 为什么感觉“没做功能就开始传图”

采集、DDR 正确性、帧所有权和断流恢复是必需基础，但画面正常时不容易直接看出来。之前在这些基础工作与通信准备之间推进，没有持续用功能清单说明完成度、可见效果和剩余项，造成用户认为 FPGA 基础处理被跳过。

修正原则：每个版本交付明确的可见功能、测试证据、未完成项和下一最小动作；协议准备不称为实体网传，后台正确性不冒称全部 FPGA 功能。

### 9.2 为什么旧车道识别“没了”

V1 为获得干净彩色主图，主显示链路不再接旧诊断输出。这不是旧识别源码都被删除，也不代表后续语义算法已迁移到香橙派；当时缺少方便的诊断切换入口，使既有能力在显示端不可见。

V4 用 KEY8 恢复可选择的基础处理和旧诊断对比，同时默认原图保持干净。今后必须准确区分“源码存在”“被顶层引用”“进入当前位流”“在当前模式显示”“现场验收通过”。

### 9.3 是否遵循原规划

职责边界总体继续采用 FPGA 基础处理、香橙派最终识别与判断。执行顺序中确实先后插入了 DDR 修复、通信应用准备、采集监测和帧所有权，未始终按用户期望的可见图像处理顺序交付。

其中 DDR 缺陷修复属于明确复现后的必要依赖；通信准备不应被表达成提前完成传图；基础功能的可见对比应更早交付。用户已明确将 KEY8 基础处理对比提前，本轮 V4 是对此的落实，不表示已经完成裁剪、缩放、多路或全景。

### 9.4 旧诊断不能被当成最终产品能力

白黄阈值、道路 ROI、连通支持、左右边界/线型启发式和斑马线连续帧确认具有诊断价值，但不等于已验证复杂道路的曲线拟合、道路边缘、可行驶区域或目标识别准确率。合成测试图上的改动像素数量，也不能换算成真实道路识别率。
