## 5. 固定分工与目标架构

### 5.1 FPGA 职责

- 单路起步的真实视频采集、格式归一、时钟域和复位处理。
- DDR 缓存、完整帧发布、读写归属、背压及异常丢弃。
- 彩色主图保留，裁剪/缩小及坐标变换元数据。
- 可选灰度、中值/其他基础滤波、Sobel 和颜色阈值辅助路径。
- 网络图像与控制收发、按键事件采集、LED/告警命令执行。
- 帧行统计、错误/丢帧计数、独立超时监测及受控恢复。
- HDMI 仅作板级调试，不承担正常最终 UI。

### 5.2 PC / 香橙派职责

- 先由 PC 验证收发、重组、保存和故障，再迁移到香橙派。
- 最终车道与虚实线、斑马线、道路边缘、信号灯、行人车辆识别。
- 多帧跟踪、置信度/新鲜度管理、驾驶意图和规则判断。
- 多路汇总、标定融合、全景、界面及最终 HDMI。
- 文件解码与测试输入服务；PC 结果和 RK3588S 部署分别验收。

### 5.3 正式目标链路

```text
CMOS1 -> 格式/帧身份 -> 干净彩色缓存与完整帧发布
                         -> 裁剪缩小/受控读出 -> UDP图像发送
                         -> PC测试端 -> 香橙派接收/识别/规则/UI/HDMI

可选基础特征 -------------------------------> 独立辅助输入
FPGA按键事件 -> 控制收发 -> 香橙派解释
香橙派命令   -> 控制收发 -> FPGA校验/LED执行/超时降级
FPGA调试支路 -> 诊断显示，不替代正式彩色传输
```

上图是目标，不代表这些箭头全部接通。首版选千兆以太网 UDP，不默认 PCIe DMA 可用，不默认增加第二块 FPGA。

扩展顺序：**单板单路 -> 双目并行 -> 相机加 HDMI 输入 -> 验证网络第四路**。四窗口、四独立输入、四相机、曝光同步和几何全景是不同验收项。

### 当前“车道检测能识别什么”

旧启发式链具备白/黄候选、左右几何边界与线对检查、实虚线初分类、图像空间偏移及斑马线连续帧候选等能力。它不证明已完成任意道路下的可靠线型识别、道路语义、真实车辆偏移、行人车辆或信号灯判断。

V4 的“颜色候选”显示白黄 ROI 候选；“旧诊断”显示历史几何/HUD/斑马线结果。它们是可观察的调试输出，不改变最终语义任务归属。

## 8. 最新 V4 发布与彩色主图限制

### 8.1 六视图不是六条独立视频流

启动默认原图；KEY8 稳定按下/释放后循环切换：

| 顺序 | 模式 | 预期含义 |
| --- | --- | --- |
| 0 | 原图 | 未叠加候选或 HUD 的 RGB565 彩色 |
| 1 | 灰度 | 现有亮度计算，重新打包 RGB565 |
| 2 | 中值 | 现有 3×3 灰度中值，不是彩色去噪 |
| 3 | Sobel | 梯度边缘特征 |
| 4 | 颜色候选 | 白黄 ROI 候选着色，无 HUD；无候选时可近似原图 |
| 5 | 旧诊断 | 历史边界/HUD/斑马线诊断，不是正式驾驶决策 |

模式按帧锁存，长按不连发；非常快的多次按键可能只显示帧边界前的最新请求。恢复与整板复位的模式保持行为以 V4 报告为准。

### 8.2 实际缓存与正式目标之间的差别

V1 曾将干净彩色直接写入主 DDR；**V4 的单个 DDR 显示缓存改为保存当前所选视图**，模式 1 至 5 时并不同时保留另一张供网络读取的干净彩色帧。

RTL 仍产生独立的 `clean_rgb/de/vs` 及其帧标签，但这不是额外外部接口或独立缓存；未被使用的支路还可能在综合中裁掉。

因此：

- V4 是调试可观察性的增量，不是正式彩色传输架构已经完成。
- 未来网络主图应接明确的 clean 支路或单独受管缓存，并绑定对应帧身份。
- 不能直接从“当前显示 DDR”取图后宣称无论模式如何都在发送彩色原图。
- “关掉 MODE”不足以证明所有 HUD、候选和斑马线绘制均关闭；需逐路径验证。

### 9.1 必须分开的格式层

| 层次 | 开发要求 |
| --- | --- |
| 规范化 RGB565 | 内部约定 R[15:11]、G[10:5]、B[4:0]；用纯色/编号证明映射 |
| 相机两拍 | 当前拼接先字节进高 8 位；顶层再有红蓝位段交换；物理输出顺序/边沿不可仅凭此认定 |
| 存储打包 | 两像素/32bit 与行 RAM/native DDR 地址单位分别核查，不把地址偏移直接当字节 stride |
| 主机参考格式 | 参考 LE 方案与相机线上顺序是不同概念，不当成现有物理 DDR dump ABI |
| 网络格式 | 包头端序、像素字节序、分片和会话协议仍须在对应阶段冻结 |

1280×720、RGB565 的紧密逻辑数据量为每行 2560 字节、每帧 1843200 字节。这是配置/算术，不是实测尺寸、帧率或网络吞吐。

### 9.2 对齐、帧与恢复

- RGB、DE、行帧标志、frame_id 和采集时间必须属于同一流水层。
- 不能将未经处理像素直接搭配已延迟的 `proc_de/proc_vs`。
- 有效行数、每行长度和首末像素分别检查，像素总数正确仍可能存在坏行。
- frame_complete 只在几何、数据及写完成条件满足后发布；坏帧不得伪装成新完整帧。
- 源 PCLK 停转时，超时必须由独立运行时基判断。
- 复位不得发布跨会话/跨复位拼接帧；当前内部状态不是已经对 PC 提供的寄存器。
- BFM/原语模型检查不证明真实 DDR 训练、物理带宽和电气特性。

### 9.3 核心用例

| 输入 | 判定重点 |
| --- | --- |
| 纯红绿蓝、黑白 | 位段、两拍顺序、存储字节顺序分别成立 |
| 单像素/大格棋盘 | 奇偶像素、跨行相位和步长不移位 |
| 行列/帧编号 | 行序、列序、帧身份无重复、重排或混拼 |
| 首末行、首末列和四角 | 全范围存在，不能裁掉 y719 使测试通过 |
| 提前帧边界 | 旧帧失效，下一合法完整帧恢复 |
| 短行/长行/奇数字节 | 错误可识别，半像素不污染后续行帧 |
| 停 DE/VS 与完全停 PCLK | 独立时基失效保护，两种故障不混淆 |
| 行中/帧尾/发布中复位 | 所有权、流水、待发布状态无跨复位泄漏 |
| 异步相位、背压与诊断切换 | 帧归属明确，原图不因诊断请求发生半帧混模 |
