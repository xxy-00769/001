日期：2026-10-19。状态：**设计/验收草案，不是已实现接口或已达性能报告**。

本轮只读源码、IP、配置、资料及历史报告。没有修改 RTL/约束/IP/工程入口，没有生成向量或运行软件参考测试、RTL 仿真、综合、时序、上板。本文件新增接口名只表示拟议语义，不表示顶层已有端口。硬件身份、备份和时钟差异见 [S1 基线登记](E:/FPGA drive/HDMI_DDR3_OV5640/docs/reintegration/03_baseline.md)。

## 1. 当前单路配置及证据

本节路径均位于 `E:/FPGA drive/HDMI_DDR3_OV5640`；行号对应本轮保留原样的文件。快照清单保存每文件 SHA256。

| 文件/位置 | 源码事实 | 不能据此推断 |
| --- | --- | --- |
| `source/rtl/hdmi_ddr_ov5640_top.v:23`、`:32` | CMOS_1 定义；SELF_TEST 默认0 | 不是双目并行缓存/传输；两套配置/打包逻辑存在不代表两个输出同时被主链使用 |
| 顶层 `:212` 起、`source/rtl/cmos_8_16bit.v` | DVP 数据/HREF/VS 在 cmos1_pclk 上升沿寄存，后两拍合一像素，GTP_IOCLKDIV 二分频 | 未证明符合当前实物摄像头的有效边沿/相位/极性 |
| 顶层 `:261` 起 | 输入选择为 CMOS1 的16bit像素、DE和 VS d0；R/B 两个5bit字段交换 | 不能仅凭 RGB565 名字推断传感器原始顺序 |

| `source/rtl/wr_buf.v:122` 起、`:303` | 16bit 分支两像素组成32bit；DDR帧区地址使用帧计数最低位 | 当前没有面向主机冻结的连续字节 framebuffer ABI |

当前源码主链路：

```text
CMOS1 DVP8 (cmos1_pclk)
  -> 顶层 d0 寄存
  -> cmos_8_16bit: 两字节拼接/分频/像素寄存
  -> i_rgb565: 交换R/B位段
  -> img_proc: 原色行缓存/灰度窗口/中值/Sobel/候选计算
  -> lane_detect: 候选着色
  -> zebra_overlay -> ADAS HUD -> proc_rgb/proc_de/proc_vs
  -> fram_buf/wr_buf -> DDR
  -> rd_buf (pix_clk) -> RGB565转RGB888 -> HDMI调试输出
```

以上是源码连接追踪，不是本轮重新综合后的网表。最终识别/规则/正式 HDMI 归 PC 后迁移香橙派；旧 FPGA 识别/本地规则显示只作诊断保留。

## 2. 当前接口：逐层记录

### 2.1 位段与两拍次序

`cmos_8_16bit` 在 DE 有效、cnt==1 时执行：

```verilog
pdata_out1 <= {pdata_i_reg, pdata_i};
```

因此**代码拼接次序**为第一个有效字节放 [15:8]，第二个有效字节放 [7:0]。随后顶层：

```verilog
i_rgb565 = {cmos1_d_16bit[4:0],
            cmos1_d_16bit[10:5],
            cmos1_d_16bit[15:11]};
```

若下游按 RGB565 解释，`i_rgb565[15:11]=R5`、`[10:5]=G6`、`[4:0]=B5`；这是当前**内部规范化解释**。实际摄像头的输出格式/首字节/颜色需用匹配资料、传感器彩条或可控注入确认，不能把这次交换当成实测正确。

配对计数器只在 reset 清零，没有在 HREF 下降或 VS 到来时显式清零。偶数字节正常行之外，奇数字节行、提前 VS、半像素复位可能跨行错配，应在后续定向用例证明；本轮不修。

### 2.2 当前时钟、行帧与复位

| 项目 | 当前代码行为 | 待实测/待验证 |
| --- | --- | --- |
| DVP采样 | cmos1_pclk 上升沿寄存数据/HREF/VS，无顶层这组 d0 的显式复位 | 实物数据有效边沿、setup/hold、PCLK频率/抖动、线缆相位 |
| 输入行有效 | HREF按高有效处理，打包器 DE 经过 PCLK检测及 pixel_clk 三级寄存 | HREF与两拍配对、空白/短行/奇数行后重新对齐 |
| 输入帧边界 | 打包器用 VS上升沿使能时钟路径；img_proc 用 vs_in 上升沿识别帧且在 VS高时不接收像素 | 物理 VS极性、脉宽、与首个有效像素间隔；不能直接宣称 VSync就是规范SOF |
| pixel_clk | PCLK 经 GTP_IOCLKBUF/IOCLKDIV /2 输出 | 原语相位、启动第一像素与 DE/data 对齐；不是任意异步时钟间的已签核CDC |
| 输入 VS域 | 传给 img_proc 的是 cmos1_vsync_d0，源于原PCLK；不是跟随三层像素数据寄存生成的输出帧标志 | 分频相位和边界采样需验证，不能用“相关时钟”替代时序证明 |
| 图像处理域 | pclk_in_test = cmos1_pclk_16bit；输出 proc_de/proc_vs 经行缓存及绘制流水 | 非固定N拍端到端延迟；必须按帧/行/像素身份核对 |
| DDR域 | 写入侧 vin_clk；控制侧 core_clk、复位 ddr_init_done | 跨域握手、帧发布归属、掉初始化/复位恢复，均未本轮仿真 |
| 显示域 | pix_clk，sync_vg自生成显示读时序；并非直接复用相机VS/HREF | 输入/显示帧率不同下撕裂/重复/读写归属 |
| 复位 | cmos_8_16bit 的 rst_n=cmos_init_done[0]；img_rstn=(done0 OR done1)；DDR独立复位；电源延迟/PLL锁定也有各自链路 | 配置完成不等于稳定帧；当前未形成统一“所有通道一起清空”的对外契约 |
| 帧号/坏帧 | 未交付与干净像素绑定的 capture frame_id、frame_bad、frame_complete 端口 | 几何诊断帧号、DDR环形帧区计数均不能直接当作来源可靠的采集ID |
| 断流 | 没有证据证明全链已具备独立时基的相机停钟检测/整帧失效通知 | PCLK停转时不能靠同一个PCLK计数器证明超时；已有其他协议超时不等于视频看门狗 |

内部 `img_proc` 会重新产生 `window_vs`，经 lane流水成为 proc_vs；它与原始物理 VS脉宽/时刻不是同一接口。`wr_buf` 对写帧同步上升沿做复位/使能，不能把这等同于已实现完整坏帧丢弃。

### 2.3 当前宽高、stride和存储次序

配置有效区为1280x720、每像素16bit：921,600像素；紧密逻辑行2560字节，紧密逻辑帧1,843,200字节。上述为配置/算术，不是已成功读回的完整帧。

- 单根16bit向量本身没有内存大小端。DVP“先高字节”与CPU存储字节序是不同层次。
- `wr_buf` 16bit分支将连续像素P0、P1打包为32bit `{P1,P0}`，首像素位于低16bit。行缓存32bit写/256bit读，再送DDR。
- 按当前常量推得每行80个256bit数据单元，`DDR_ADDR_OFFSET=640`，单位是当前控制器原生地址单位，**不能写成640字节 stride**。
- `fram_buf.LINE_ADDR_WIDTH=22`，`wr_buf`使用 `{rd_frame_cnt[0], rd_cnt}` 形成帧区地址，非声明两张紧密排列主机字节数组。混合位宽RAM地址映射、DDR字节lane、返回重组和末行完整性仍需已知像素回读验证。
- 当前没有主机图像导出接口，所以**当前物理DDR dump的字节序/帧ABI未冻结且未实测**。不得从 `{P1,P0}` 一行代码推断全部存储布局。
- HDMI RGB565转RGB888当前使用低位补0，即最大通道248/252/248；这不是颜色丢失故障的独立证据。软件对照应明确用补0还是位复制扩展，不能混用两种参考。

## 3. 未叠加彩色的候选接入点

**下表只定位候选，不代表现在已有可供DDR/网络使用的干净彩色出口。**

| 候选点 | 与候选着色/HUD/DDR的关系 | 延迟和后续条件 |
| --- | --- | --- |
| 顶层 `i_rgb565`，随同 `de_in_test/vs_in_test/pclk_in_test` | 位段交换后，所有img_proc行缓存/候选绘制之前，最直接的原色候选；当前DDR并未连接此处 | 只能携带自己这一层的有效/帧语义，不能把raw像素配proc_de/proc_vs；还需验证原始VS与分频像素相位及坏行配对 |
| img_proc内部 `c_pix[15:0]`、`c_pix[16]`、`window_vs` | 原色行缓存后、lane_detect着色前；同时是zebra_detect的分析输入，内部wire/reg未对外导出 | 需未来明确导出并保持三者同拍、补齐ID/错误语义；行等待、右边界tail、末行flush不是简单固定N拍 |
| lane_detect流水内 `final_base` 与对应final_de/final_vs | MODE4情况下保留的底图来自原色，但最终rgb_out可被候选paint覆盖，其后还有zebra/HUD | 可作流水追踪证据，不将内部final_base直接称为正式接口；模式变化时底图可能是灰度/边缘而非彩色 |

当前 `lane_detect` 将白/黄候选绘为 `07E0` / `07FF` 等诊断色；zebra检测分析的是未着色 `c_pix`，但其 overlay 接收 lane已处理画面，ADAS HUD再叠加，最后 `proc_rgb`进入DDR。

`MODE=0`最多说明某些mode选择/候选着色行为，不会自动关闭 `ZEBRA_ENABLE`、`ADAS_ENABLE`及其他绘制/缓冲行为。后续不能以单一MODE值验收干净主图。

拟议目标拓扑：

```text
CMOS1规范化彩色 + 对齐的帧行信息
  -> 干净主图缓存/发布 -> 后续受控传输 -> PC/香橙派
  -> 可选灰度/中值/Sobel/候选特征 -> 独立诊断显示
```

主图与诊断的像素/帧号/复位/丢帧相互独立验收。候选着色、HUD开关不得改变干净主图内容、行长、帧长或帧归属。具体采用哪个候选点、如何经过DDR以及端口定义，留给后续获授权的小改动，不在S1接线。

## 4. 目标单路契约草案

以下均为**待实现/待验证**，不是现有行为承诺。接口采用采集流和完整帧发布两个层次，避免把收到SOF误认为帧完整。

| 字段/语义 | S1拟议目标 | 状态/未决项 |
| --- | --- | --- |
| source_id | 固定CMOS1单路，双目暂不复用此ID | 拟议；物理镜头对应需现场标记 |
| pixel_rgb565 | [15:11]R5、[10:5]G6、[4:0]B5；主路保留规范化彩色，逐像素不做候选绘制 | 位段草案固定；实际输入交换是否正确待彩条/实测 |
| DVP两拍 | 采集适配层依据实物确定首字节与边沿，再映射规范像素；错误行/复位丢弃半像素 | 当前代码先高后低已记录；物理输出顺序待确认，不能先改传感器配置 |
| width/height | 首版1280x720有效区，不含消隐；每行恰1280、每帧恰720行 | 配置基线，实际测量待做；不承诺有效30fps |
| stride/frame size | 软件参考紧密布局2560B/行、1,843,200B/帧；若后续DMA有padding必须显式描述 | 不是现有DDR ABI；不擅自改DDR地址 |
| 参考存储字节序 | 建议软件参考RGB565_LE：每像素低8bit先存，下一字节高8bit | **提案，未实现/未冻结为网络顺序**；物理DDR映射需独立证明 |
| clock/valid | 同一pixel_clk上升沿采样rgb及valid；valid=1表示一个像素，不允许无声明丢像素 | 接口草案；无ready的相机不可无限背压，溢出应判坏帧 |
| 行边界 | 输出SOL/EOL或等价x/y；首像素x0，末像素x1279，y0..719；消隐不增加坐标 | 可由明确计数器等价表达，实际端口形式留后续；不能只靠像素总数发现坏行 |
| SOF/VS | 规范SOF为1拍标记，位于首valid前1拍；每帧只一次，与该层像素同域；不得把物理VS电平当规范SOF端口 | 拟议；输入VS极性/消隐容差待实物确认；现有window_vs尚未证明满足全部契约 |
| frame_id | 建议内部32bit，每个合法检测到的输入SOF分配一个ID，模2^32递增；坏/丢帧保留间隙，不重新编号掩盖丢帧 | 未实现。新SOF即使打断旧帧也给新ID；源端抖动/毛刺如何认定SOF需适配层实测参数 |
| reset/session | 任意中途复位清除半像素、当前帧有效、待发布和相关流水；等待重新初始化及下一个可信SOF，不发布跨reset数据；ID从0重起须配会话代号 | 未实现统一语义；session分配/位宽待下一接口冻结，不构建网络协议 |
| frame_bad | 短/长/奇数字节行、提前SOF、缺行/多行、停流、溢出、DDR失步/重初始化均使当前帧失效；记录原因/计数 | 未实现完整路径。流式像素可能已暂写，不能把“写过像素”当“已发布有效帧” |
| frame_complete | 只有几何、数据完整性和缓存写入完成均满足才发布{ID,尺寸,帧区}；坏帧绝不发布valid完整帧 | 未来设计；没有锁定可靠归属前不得允许下游读写同一帧区 |
| 断流/恢复 | 独立运行时基检测T_stop，时钟停止同样可失效；恢复后重新配对、等待可信SOF和整帧完成 | T_stop、正常间隔容差、恢复帧数/时间均待测后冻结，没有当前达标值 |
| 网络字节序 | 像素字节顺序、头部整数端序、分片与帧身份编码 | **全部待后续阶段冻结**；本轮不增加图像包头、分片或UDP协议 |

软件参考字节例子：规范红F800 -> `00 F8`，绿07E0 -> `E0 07`，蓝001F -> `1F 00`。这些是拟议内存格式，不是相机在线字节/UDP字节顺序。

## 5. 后续验收输入与判定

本节**只定义用例，没有生成/运行用例**。确定性模式要求逐像素、逐字节、帧/行边界误差为0；实拍色卡受曝光/白平衡影响，不能要求其直接输出F800。实拍容差需预先固定且注明AWB/AEC状态。

软件参考、RTL仿真和上板各自证明不同事实，不能相互替代。所有后续结果都需绑定源码/IP/FDC哈希、输入seed/图样版本、复位/时钟条件及原始输出证据。

| ID/输入 | 软件参考需证明 | RTL仿真需证明 | 上板需证明 |
| --- | --- | --- | --- |
| V01 纯红/绿/蓝、黑/白，每色整帧 | 位段与字节pack/unpack可逆；LE参考值；RGB888扩展规则明确 | 在规范入口F800/07E0/001F逐像素相同；原始DVP入口另测两拍与R/B交换，DE/SOF无偏移 | 传感器彩条或可控源的实际色序、首字节、采样边沿；保存原始捕获，不能仅目视HDMI |
| V02 1像素棋盘及8x8等大格棋盘 | 邻像素/边界/行步长预期可重建 | 不发生奇偶像素互换、合并、漏拍，跨行首列相位正确；诊断开关不改主图 | 实际通路可控源下格数/边缘/稳定性；拍摄棋盘只辅助空间观察，不能代替数字逐像素比对 |
| V03 行列/帧编号 | 用固定公式编码x/y/frame，生成期望序列并识别重排/重复 | 例如三相连续帧分别编码x、y、frame；检查720行、每行1280、ID与内容绑定、无旧帧混入 | 通过可控图样/捕获回读比对；运行时长/帧数先固定并记录，不能只看一张图 |
| V04 首末行/首末列特殊哨兵 | 四条边各用不重复图样，四角单独编码 | y0/y719、x0/x1279全部存在；尾行flush、右端tail、相邻帧边界无丢失/复制 | 捕获完整有效区，包含四边；不得裁掉最后一行来宣称通过 |
| V05 提前帧边界 | 在指定行0、1、359、718与半像素位置插入新边界，期望旧帧invalid | 新SOF截断旧帧只产生一次错误；不混帧；按下一个完整合法帧恢复 | 有可控源/安全注入条件才测；不能靠拔插替代精确提前边界向量 |
| V06 坏行 | 每帧任选行输入2558/2562字节和2559/2561奇数字节，另测HREF短脉冲 | 短/长行、奇数半像素均判坏；下行/下帧配对复原；空白不计像素、不以总数补齐掩盖短行 | 可控源覆盖；实拍相机是否出现此故障须独立统计，未出现不等于处理已验证 |
| V07 截断/多行帧 | 719行、721行、缺末行、重复行，期望错误种类明确 | frame_complete不得发布；ID/帧区/统计一致；恢复帧不携带陈旧行 | 有捕获工具才证明实际发布/错误计数；HDMI重复旧画面不算“恢复正常” |
| V08 断流两类 | 时钟继续而DE/VS停止；PCLK完全停止，参考超时事件 | 独立时基超过预设T_stop使帧invalid；恢复后从可信边界开始，缓存有界且不伪造新帧 | 不随意带电拔摄像头；用安全可控条件测时间戳、帧龄、停钟与恢复，记录计时基准 |
| V09 复位 | 首字节后/行中/帧尾/正在发布时复位，参考状态归零 | 半像素丢弃、流水/帧区失效；reset持续时无有效发布；跨域释放/DDR重初始化不混帧 | 依据授权的安全复位路径测冷启动/热复位/DDR再初始化，绑定具体位流；本轮未执行 |
| V10 异步与诊断对照 | 输入/显示帧率可独立、黄金主图固定 | 多组相位/消隐长度/背压；主图开关HUD/候选不变；读写帧所有权和drop原因可核对 | 长时采集实际FPS/丢帧/延迟、显示与输入不同步时的行为；网络性能留后续而非本轮预设 |

具体可复现的编号图样草案：

```text
phase=frame_id%3
phase0: pixel=(x & 0x07ff)，用于检查列序
phase1: pixel=(y & 0x03ff)，用于检查行序
phase2: pixel=(frame_id & 0xffff)，用于检查跨帧污染
覆盖四边/四角时另加固定哨兵，金标准同时记录每个坐标
```

这不是用于实际道路的显示画面，也不是现成RTL测试源；允许其像素颜色不直观，关键是可定位坐标。后续可加强为带seed的确定性全帧模式，需先冻结公式，不能对测试失败后更改预期。
