# 小步复现与再集成计划

日期：2026-10-19。**本文件仅为后续阶段计划，不授权或启动其执行。**本轮到新增四份报告结束。

## 1. 阶段纪律

- 保留旧工程及归档，继续以现有采集/DDR/HDMI模块为基础；不集中搬目录、升级IP、替换全部RTL或清理旧产物。
- 每阶段只改变一个可验收的行为。下一阶段开始前报告改动文件、实际命令、证据路径、验证等级和未验证项。
- 源码存在、静态检查、RTL仿真、综合、布局布线时序、上板分别登记。软件测试和模拟输入不算真实硬件验收。
- 涉及引脚/电压/时钟/DDR/PHY的变更须有对应实物资料，不能以旧例程或旧板记录猜测。
- 后续构建先使用独立输出目录并显式列出输入，不直接运行会删旧通用位流的入口脚本。不得因此修改历史产物或原始记录。
- 本轮没有自动commit、下载或Flash操作；后续硬件动作按当时用户授权执行。

阶段状态：S0报告已完成；S1至S10均待执行。以下路径仅指定模块范围，未承诺新增文件名已经存在。

### S1：实物身份、版本快照与单路接口规格

允许范围：资料和版本清单、独立备份目录、单路规格与用例；暂不修改RTL/引脚/IP。

1. 记录实物MES50HP核心/底板版本、FPGA/DDR/PHY丝印、摄像头模组、接线和供电，补齐匹配的电路资料；香橙派尚未到场也可先做PC端。
2. 对当前HEAD、README脏改动、全部未跟踪内容、忽略但需复现的IP/位流及仓库外归档做独立快照。清单含原路径、大小、时间、哈希，并抽查恢复；不以哈希代替备份。
3. 固定单路接口：选中相机、RGB565位段及字节序、宽高/行步长、帧/行有效、复位时序、未叠加彩色出口、帧号/错误语义。
4. 只读核查有效PLL/STA时钟与根FDC文字差异，确定后续时序签核范围，不先改到“看起来一致”。

验收：实物/资料/工程三方对应；存在恢复可用的快照；接口与测试用例无未说明歧义。硬件不在场则文档部分可完成，实物核验仍待办，不进入依赖它的引脚变更。

停止条件：板卡/DDR/PHY身份不明、资料冲突未解、备份不能恢复。不得以调整约束绕过。

### S2：复现单路与DDR最小故障，不先修大系统

允许范围：独立测试台/驱动及复现脚本、证据目录；主RTL仍不改。

重点复现 `source/rtl/wr_cmd_trans.v`、`rd_buf.v`、`fram_buf.v` 既有风险：

- 最后一拍前有返回空隙，完成脉冲只能对应一次有效返回。
- 逐像素编号帧覆盖第0至719行，含最后一行，禁止屏蔽边缘以通过测试。
- 摄像头/DDR/显示异步相位、不同帧率、读写背压、缓冲绕回、提前VS/坏行、停流后重启、DDR重新初始化。
- 记录帧发布/读取归属，不只检查“显示有画面”。

先检查PDS/仿真工具和许可证、IP模型，再改归档测试脚本的运行入口到新的独立驱动；不覆盖归档。工具不可用时继续完成向量/断言与可运行主机测试，但RTL仿真保持未验证。

验收：对当前源码形成可重复失败/通过的定向结果，绑定输入哈希和日志；解释旧隔离实验与当前配置的差别。

停止条件：测试台自身帧同步/复位不可信，或失败不能定位到单一行为。不得直接复制历史修复。

### S3：DDR局部修复与可靠性回归

仅在S2明确复现后，按一个缺陷一次提交范围推进：

| 子步 | 候选变更范围 | 检查 |
| --- | --- | --- |
| S3a | `source/rtl/wr_cmd_trans.v`及对应测试 | 返回空隙/最后拍/复位完成脉冲 |
| S3b | `source/rtl/rd_buf.v`及对应测试 | 全720行、预取边界、复位重入 |
| S3c | 确有证据时才动`fram_buf.v`或相关控制 | 帧归属、init_done和复位/停流恢复 |

不把三项自动合成一轮修改；不改DDR IP内部、电压或引脚来掩盖控制错误。每子步先单元仿真再全帧回归，进入综合/PNR后分别记录时序范围及未约束路径；上板只使用与报告一致的位流。

验收：旧失败用例转为通过，正常全帧不回退；实际硬件帧/行连续性与复位用例单独通过，未上板则只报告已达到的层级。

### S4：未叠加彩色主图与诊断旁路

候选范围：`source/rtl/img_proc.v`、主顶层及必要的诊断连接、对应测试；不整体改写预处理器。

先明确延迟对齐和行帧边界，再提供稳定的未叠加彩色出口。让主DDR保存干净彩色，诊断HUD在独立显示支路使用；旧候选/几何/斑马线继续作为对照，不承担正式识别。

验收：纯红/绿/蓝、棋盘、行列编号及真实相机样张；主路逐像素对照，首末行与VS/DE对齐；诊断开关不改变主图。必须实际检查色序，不只看显示“颜色差不多”。

停止条件：MODE=0仍被其他overlay改写，或关诊断导致主路帧/行长度改变。

### S5：千兆网实物小包与双向控制测试

候选范围：新增隔离的网口模块/测试端；PHY约束仅在S1实物资料核对后新增，保留厂商原版RAR。

先证明复位、协商、ARP、UDP发送及PC反向接收；测试内容为序号/计数器和LED诊断命令，不接图像、不接驾驶规则。核查RGMII/MDIO时钟域及IO时序，厂商固定字符串例程不算验收。

验收：PC抓包与板端计数一致；坏包/重复/过期/断链/重启/重连有明确行为；LED诊断命令按租期退出。吞吐、丢包、收发方向分别量测。

停止条件：只发不收、PHY速度不明、没有匹配约束或外部IO时序证据。此阶段不迁移PCIe。

### S6：已知帧协议、重组与真实彩色UDP

分成三个小步，不同时完成：

1. 冻结应用协议及PC重组器，先用软件注入分片，测试乱序/重复/缺包/截断/重叠/越界/会话重启/超时；队列有界。
2. FPGA发送已知编号彩色帧，PC收齐后逐字节比较；证明背压与帧缓冲归属，不允许新旧帧混拼。
3. 接S4真实彩色帧，再加入有软件金标准的裁剪/缩小模块；可选特征流最后单独接入。

候选范围：新网络帧模块、DDR受控读出、PC接收服务及各自测试。旧结果库与图像协议并存，避免破坏原回放证据。

验收：保存原始帧和重组统计；内容、尺寸、色序、帧号一致；定义并量测有效FPS、有效载荷速率、丢帧、延迟和恢复。无数据时不得显示为“最新正常画面”。

### S7：按键事件与LED命令正式闭环

候选范围：从v11逐模块引入消抖/事件思想、控制协议和LED执行器；不整体复制`lane_local_ui`本地规则链。

FPGA按键事件发往PC测试端，后由香橙派解释；命令返回只驱动LED/告警输出。旧合成规则模式必须显式隔离且不能作为正式识别输入。

验收：按下/长按/抖动/释放后重按、一事件一次、重包幂等、会话重启、命令过期和失联降级。LED输出和主图独立；不是仅看HUD颜色。

### S8：迁移香橙派与正式识别/规则/显示

先无AI预览，再逐项识别与多帧规则；最终车道线型、斑马线、道路边缘、信号灯、行人车辆由ARM承担。速度/距离无实测来源就标为模拟，不据此声称真实TTC或安全可变道。

验收：RK3588S实机收帧、已知帧对照、模型及数据版本、场景正确/误检/漏检、决策日志、香橙派HDMI和LED命令；PC性能与ARM性能不混用。U盘场景后续验证“解码像素→FPGA处理→回传”的实际路径。
