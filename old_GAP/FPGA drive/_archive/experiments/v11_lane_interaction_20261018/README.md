## 文件与行为

- `source/lane_button_events.v`：4路低有效输入、双级同步、独立消抖、释放后允许下一次事件；
  上电一直按住不触发，长按不连发。默认10ms（按37.125MHz估算）。
- `source/lane_snapshot_cdc.v`：256位快照四相握手，源锁存到确认；忙时丢弃并饱和计数。
  双域必须共同异步复位、各自同步释放。不是视频图像传输接口，不保证每帧送达。
- `source/lane_change_control.v`：未知/虚线请求/实线阻止/告警状态；默认0.5秒结果期限、
  2秒请求期限（同一时钟估算）。严格前进16位帧号，支持回绕，拒绝重复/倒序。
  超时后也不重新接受旧帧号；源独立重启或跨越32768帧需公共复位开启新序列，
  不用“重复旧帧重新有效”换取自动恢复。
- `source/lane_rule_test_source.v`：每120个显示帧轮换双虚线、左实右虚、左虚右实、未知，
  **合成规则输入，不分析摄像头**。默认视频时钟下每场景约4秒，不是实测时间。
- `source/lane_change_overlay.v`：右上角状态面板、帧号、请求方向及箭头；仅在VS边沿更新
  显示状态，面板外RGB565原样通过，不增加像素寄存延迟、不改DE/HS/VS。
- `source/lane_local_ui.v`：显示时钟域按键、控制、叠加封装。`RULE_TEST=1`常驻
  `RULE TEST`；`RULE_TEST=0`常驻`LOCAL CANDIDATE`，接现有v8启发式快照。

按键顺序为 `key_n[0]`左、`[1]`右、`[2]`强制请求、`[3]`取消/直行。
**逻辑顺序不是物理管脚号。实物MES50HP及8键已由用户确认，采用板载KEY1..4，
不需要外接按键或重新接线。** 见下方“硬件资料补充”。本轮未获得下载授权。
取消优先，左右同时按取消，单独强制键不产生方向；方向+强制同时有效。
虚线显示黄色`DASHED REQ`，只表示规则允许提交请求，不意味着变道安全。
实线显示橙色`BLOCKED`，强制时红色`SOLID ALARM`，仍不输出变道执行方向。
无有效双侧类型、坏帧或过期时显示`UNKNOWN`，撤销请求和告警，不做驾驶结论。
不接真实车辆执行器，原有LED仍为初始化/心跳，未伪装为本功能告警灯。

## 隔离接入与门槛

`tests/prepare.py` 读取当前主顶层，仅在新时间戳运行目录生成接入草稿：
导出 `img_proc.adas_valid/adas_snapshot`，经快照CDC送显示域；在DDR读出之后、
原HDMI RGB输出寄存器之前叠加新面板；原图像处理、DDR、时序发生器和主文件不变。
生成副本显式声明显示时序wire，避免旧源码隐式声明在ModelSim SV下被拒。

`LOCAL_RULE_TEST`只选择规则来源，不改变视频来源；`SELF_TEST`仍默认0，
所以`RULE TEST`可以叠在真实摄像头画面上，**不能因为有真实背景就称规则来自识别**。
新面板是最新状态显示，不是空间检测框；标明源帧号，不声称与DDR当前显示帧严格对应。
显示最多等待下一个正常VS刷新；摄像头源钟停止时，控制看门狗仍由显示时钟推进。

早期语法测试草稿的`generated/integration.json`保留当时未确认引脚的历史状态。
本轮确认后的独立构建由`build.py`生成，复制完整厂商IP、追加四键约束，
不修改主约束、不运行主`flow.tcl`。本次仅构建`RULE_TEST=1`，
未实例化新增相机快照CDC；相机候选模式的物理CDC审查与构建仍待办。
逻辑仿真不证明物理CDC、总线保持窗口或布线时序，不以宽泛假路径隐藏问题。
