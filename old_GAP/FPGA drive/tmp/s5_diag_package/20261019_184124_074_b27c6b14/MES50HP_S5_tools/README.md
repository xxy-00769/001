# 在另一台电脑使用 MES50HP 网口工具

## 当前能做与不能做的事

本包是 **S5 诊断通信工具，不是视频播放器**。不依赖当前开发电脑的网口，
也不依赖整个 FPGA 工程或第三方 Python 包。

- 已开发：32 字节诊断协议、电脑客户端、软件模拟端、独立应用层 RTL。
- 尚未接通：主工程到 MAC/RGMII/PHY 的实体链路。
- **当前 V1 位流仍然只通过 HDMI 输出视频，不会发 UDP。现在运行客户端收不到板端应答是预期，不应反复改电脑网络排查。**
- 后续实体链路版本完成后，先用本包验收小包收发，再开发视频传输/重组/显示。
  不能用 VLC、浏览器或本包直接播放当前 FPGA HDMI 图像。

## 不用开发板，先验证另一台电脑可运行工具

1. 将整个工具包 ZIP 通过 U 盘或你现有的文件传输方式带到另一台电脑，解压到独立目录。
2. 该电脑需有 Python 3.10 或更新版本。命令行运行 `py -3 --version` 检查；
   若只有 `python` 命令，下文把 `py -3` 替换为 `python`。无需 `pip install`。
3. 在解压目录打开两个 PowerShell 窗口，第一个运行：

```powershell
py -3 .\link.py emulator --bind 127.0.0.1
```

4. 第二个运行：

```powershell
py -3 .\link.py client --board 127.0.0.1 --bind 127.0.0.2 --count 10 --led 1 --lease-ms 2000
```

应出现 `Session ... established`、`seq=...`、`lease=...` 等诊断记录。
LED 状态先为 1，租期结束后为 0；此处是**软件模拟状态，不是板上灯**。
结束后第一个窗口按 Ctrl+C 停止。回环成功只证明这台电脑的软件可用。

## 后续实体网口位流交付后才执行

以下地址为 S5 预留方案，**不是当前 V1 已实现的配置**。最终应以新位流发布记录为准。

```text
摄像头 -> FPGA -> HDMI -> 现有显示器（保持不变）
              |
         板载 ETH1（需核对丝印与资料）
              |
             网线
              |
       另一台电脑的有线千兆网口
```

原开发电脑可继续通过 USB/JTAG 给板子下载，无需替换开发电脑；
另一台电脑只负责接网线和运行客户端。不把 HDMI 线插进电脑网口，
也不需要让两台电脑互相转发视频。

1. 用网线直连板载已确认的 ETH1 与另一台电脑的有线网口，摄像头、供电和 HDMI 不动。
2. 先记录另一台电脑该有线网卡原来的 IPv4 设置，测试结束后恢复。
   在 Windows 的网络适配器设置中打开该**有线网卡**的 IPv4 属性，设置：

| 项目 | 预留值 |
| --- | --- |
| 电脑 IPv4 | `192.168.50.105` |
| 子网掩码 | `255.255.255.0` |
| 默认网关、DNS | 留空 |
| FPGA IPv4 | `192.168.50.11` |
| 双方 UDP 端口 | `8000` |

如果其他网卡已有 `192.168.50.0/24` 网络，先反馈冲突，需同时调整新位流与工具的地址。
不要修改 Wi-Fi 地址，不建网桥，不启用 Internet 连接共享，不全局关闭防火墙。

3. 确认网卡协商速率为 **1.0 Gbps**；100 Mbps 不能按千兆验收。
   若 Windows 防火墙阻止收包，可在管理员 PowerShell 添加限定地址和端口的规则：

```powershell
New-NetFirewallRule -DisplayName "MES50HP S5 UDP test" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 8000 -LocalAddress 192.168.50.105 -RemoteAddress 192.168.50.11 -Profile Any
```

测试结束后可删除这条专用规则：

```powershell
Remove-NetFirewallRule -DisplayName "MES50HP S5 UDP test"
```

4. 在工具目录运行：

```powershell
.\run_windows.cmd --count 20 --log .\s5_first_test.json
```

或直接运行：

```powershell
py -3 .\link.py client --board 192.168.50.11 --bind 192.168.50.105 --count 20 --log .\s5_first_test.json
```

日志文件采用“新建但不覆盖”；再次测试请换日志文件名。预期先握手，然后每半秒显示应答序号、
LED 请求状态、剩余租期、板端接受命令数和电脑往返耗时。`timeouts` 是应用请求超时次数，
不是视频丢帧率，也不是已测得的物理网口丢包率。

5. 后续硬件 LED 映射完成后，可测试一次 2 秒租期：

```powershell
.\run_windows.cmd --led 1 --lease-ms 2000 --count 10 --log .\s5_led_test.json
```

只在租期内生效，重复序号不能延长租期。旧会话停止活动 5 秒后失效；
重开客户端遇到 `BUSY` 时等至少 5 秒再重试。工具不自动续租 LED，也不执行驾驶控制。
断网后尚无可靠 link 信号时，最多受租期/会话超时约束，不能承诺拔线瞬间灭灯。

## 出错时反馈什么

- 使用的新位流名称及 SHA256，实际接的网口丝印。
- 命令行完整输出及 JSON 日志。
- 该有线网卡 IPv4、掩码、协商速率截图，不用提供其他账号或网络密码。
- 若无应答，可在该网卡抓取 `arp or udp.port == 8000`，保存抓包文件。
  现阶段不要求 `ping` 成功，因为 ICMP 尚未实现/验收。
- 同时说明 HDMI 是否仍流畅。客户端没有画面窗口不代表视频故障，本阶段本来不收视频。

## 什么时候才能在电脑看到画面

需要后续版本依次完成：实体网口双向验收、已知图案分片重组、真实彩色取帧与发送。
届时会提供对应的图像接收/显示程序和明确的尺寸、色序、帧率、丢帧统计。
这次工具包不提前假装已具备这些能力。
