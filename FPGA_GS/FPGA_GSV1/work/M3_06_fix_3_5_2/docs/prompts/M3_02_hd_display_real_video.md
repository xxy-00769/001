## 2. 最新端口架构，覆盖旧文档中单网口的最终用途

- 本轮联调：网口1仍同时承载PC→FPGA右摄、FPGA→PC前摄原图、按键/判定/心跳。
- M3收尾分流：网口1连接电脑/视频源，负责右摄VIDEO_IN及必要会话维护；网口2连接香橙派，负责前摄FRONT_RAW、按键事件、判定/告警和相应ACK/心跳。
- 先把本轮M3功能和真实视频稳定，再另一个集成步骤启用网口2；双网口上板闭环完成后进入M4真实识别。本轮不提前声称双网口完成。
- 现在把像素业务和控制业务目的端点集中配置，避免把单端口地址/会话硬编码进所有模块。不提前实现通用交换机、桥接或整套新网络框架。
- 后续两个独立链路的会话/失联状态必须各自维护：右摄文件发送端重启不能清掉香橙派判定会话，右摄断流不能误报香橙派失联，反之亦然。最终只由香橙派链路提供驾驶判定，电脑测试模式不得与它争写。
- 本轮不增加第二个前摄网络读者。后续网络读者从网口1迁移到网口2即可，不能无故复制DDR上传读取。
- 网口2的引脚、PHY、时钟、复位和延时以后根据板卡原理图/约束核实，不能仅凭旧例程注释或接口外观照搬。

## 3. HDMI显示适配：解决确定存在的降采样

当前代码实际输出800×480，内容区640×360，四格每路约320×180；新显示器不会自动让这些像素恢复成高清。原始输入/DDR/网络协议继续保持1280×720 RGB565，不同时升级摄像头到1080p。

1. HDMI-OUT改标准1920×1080时序。先依据MS7210、器件/输出接口能力、现有PLL和时序余量选择刷新率：目标60Hz；若148.5MHz无法可靠闭合，可交付标准1080p30/74.25MHz，并明确原因与实际时序。不要为追60Hz反复牺牲稳定性，也不能悄悄退回800×480冒充完成。刷新率与源视频帧率分别报告。
2. 单画面优先1280×720像素1:1居中，避免无谓放大，边缘用于状态文字；默认不必再做复杂的单画面全屏插值。四宫格每格960×540，从各路720p完整原图直接缩放，不经过旧320×180中间结果、不裁掉视野、不改变16:9比例。采用资源可控的确定性缩放方式，说明采样方法；不以锐化掩盖低分辨率。
3. 修改真实读地址/行预取/缩放及窗口坐标，不能只改PLL和同步计数。核对每帧行数、行尾、窗口边界、跨帧旧返回排空和欠载恢复。显示预取容量及DDR预算按新规格计算。
4. 所有坐标位宽、滤波行深度及DRM映射、KEY5/6帧边界切换、OSD对齐一起适配。四格滤波边界隔离；保留来源中文、模式、按键提示、驾驶反馈。文字不遮住大片有效图像。
5. 不沿用800×480的小屏硬编码作为新主链路；历史位流保留即可，不为了双屏兼容引入额外运行模式。
6. 最差setup曾只有+0.540ns，PLL已4/5，必须核查时钟复用/分配和约束。不得通过随意false path或放宽约束假造通过。现有外部IO未完整签核的范围如实报告。

## 4. 电脑右摄改为指定视频文件

1. 在现有统一工具增加视频文件选择、播放/暂停/循环及合成测试源切换；给出类似`--video "E:/videos/road.mp4" --loop`的真实可运行命令，以最终实现为准。道路场景视频由用户指定，不下载素材、不擅自查找私人视频。
2. PC解码文件→按比例缩放并补边为1280×720→转换RGB565小端→现有UDP VIDEO_IN发送。FPGA继续接收原始像素，不能把MP4/H.264字节直接塞进当前协议。视频源标签/帧号是可选调试叠加，不强行遮挡道路内容。
3. 优先核对现有Python环境、OpenCV/PyAV或FFmpeg是否可用，选择一条成熟解码路径，不造解码器。不得擅自安装软件；如缺依赖，报告准确所需项，同时完成其余独立工作。真实文件发送是本轮必需项，不能只保留合成源并称完成。
4. 按视频时间戳/帧率播放，发送来不及时跳过旧源帧、保持有限队列，不把30秒片段越播越慢。暂停/EOF/停止明确区分；恢复或换源不发布半帧。实时发送不得造成无限解码预读或内存增长。
5. 保留FRONT_RAW预览、保存PNG、模拟判定、停止右摄及统计；前摄增加原尺寸查看/适应窗口。保存必须是原始1280×720像素，不保存缩小的预览。

## 5. 发送性能：解决约1fps，不展开无界调优

先测解码/缩放/转换、图案生成、每帧分包/发送及逐包等待耗时，找出主要瓶颈。避免Python逐像素循环和每包重复不必要分配；采用现有库的批量转换、缓存、有限队列和合理节奏。UDP分片/MTU沿用已验证协议，不能不协商就改包长，也不能用无界突发压垮FPGA接收FIFO。

先争取真实右摄稳定5fps，进一步目标15fps；前摄维持已观察到的约5fps，再按预算提高，最终720p30目标保留。不要为了右摄速度让前摄或按键失效。统计区分请求fps、实际发送完整帧fps、FPGA发布帧数/丢弃帧数、PC前摄完整接收fps；如需新增板端计数，最小扩展并同步文档。

至少记录一个60秒双向收发并发测试；软件回环与实物测试分开。没有板卡操作权限时交付可执行测量步骤，不编造板上吞吐。必要检查通过就构建交付；有真实性能瓶颈则记录具体耗时和未达指标，不能在没有新证据时循环调参。

## 6. 清晰度定位与必要验证

- 新显示全尺寸生产路径：真实720p四来源、1080输出完整行/列、单画面与四格，使用不同来源标识、像素坐标、细线/网格定位采样，检查全部显示区域、来源和窗口接缝；不能只用压缩高度证明1080路径通过。仅保留与改动相关的CDC、旧返回、双读者、滤波/OSD和按键回归。
- 文件发送/解码做真实可解码样例检查，可在临时目录本地生成短测试视频；覆盖暂停/循环/EOF/换源、接收缺包丢整帧恢复、并发CONTROL。测试用生成文件明确标为夹具，不冒充比赛道路素材。
