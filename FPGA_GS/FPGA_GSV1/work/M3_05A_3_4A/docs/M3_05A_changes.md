# M3-05A 3.4A 最小候选

这是一次被动诊断候选，不是已确认恢复HDMI的修复版。尚无实物首失败环节证据，不改变HDMI输入采样、PLL或MS7200寄存器。

以3.3实际发布包source完整复制到独立目录work/M3_05A_3_4A。3.4失败源码和报告已冻结于deliverables/FPGA_GSV1_M3_05_3_4_WIP_NO_BIT_20261021_104224.zip，其SHA256已复核。原工作目录没有被覆盖；后续构建入口指向本候选，不能混用根目录3.4代码。

3.4新增的摄像头IO模块、下降沿分频、HDMI额外tuple寄存均不进入本候选。cmos_8_16bit、hdmi_input、摄像头/MS7200配置以及网络15fps相关RTL均与3.3逐字节相同。没有为覆盖相同文件声称HDMI已修复。

从用户确认HDMI正常的2.1到3.3，核对HDMI输入引脚、接收配置/I2C、复位、格式和有效像素监测、capture_pipe、来源2所有权及写流水：核心文件与接线一致。实际flow引用本地冻结文件和IP，没有发现指向错误旧副本。共享显示由M2读者改为m31读者、三端口DDR扩展为五端口及前摄独立读者属于已有功能差异；3.2与3.3的这些实现相同。3.2到3.3变化集中于网络四个RTL，本候选保留这些吞吐修复。完整差异和哈希见reports/compare_baselines。

实际只增加一处状态观察：rtl/board/m35a_hdmi_status.v，利用已有输入帧计数、format、capture healthy、DDR发布计数、选中及显示DE/保护信号；单bit同步，在50MHz域判定L0～L7，再复用既有mailbox送到OSD。fram_buf仅导出两个被动信号，不改写入、所有权、仲裁或读取。m31_video_output仅传递3bit诊断，原像素、同步、滤镜流水不变。m31_osd在左摄标签旁显示状态码，异常区不再一律建议改分辨率；不裁图或遮盖数据问题。

约束从3.3发布包出发，不加入3.4无资料依据的±1ns外部输入预算；同时保留摄像头PCLK及其原÷2相关路径检查，不恢复错误异步切断来伪造全板通过。摄像头代码本轮不整改，若此真实既有问题仍在，交付必须单列，不能写全板STA已通过。HDMI/摄像头/RGMII外部引脚电气预算沿用发布基线的未完整签核边界。本轮输出仍148.5MHz、2200×1125、正HS/VS、1080p60/VIC16。

仅运行新增状态及OSD定向检查、生产改动范围等价检查、发布源码/引脚/工程引用比对以及必要综合布局布线/时序审查；未改摄像头全尺寸、网络软件回环、滤镜算法验证不重跑。未烧录、未固化、未安装依赖、未改电脑配置。后摄绿点、30fps、网口2和M4明确不在本候选范围。
