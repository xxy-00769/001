# M1-02 显示读者与帧槽

正式来源仍为 CAM0=前摄、CAM1=后摄；source ID 为 0/1，保留相同的 2 位来源地址布局以便后续扩展。没有新增多模式通用框架。

## 数据路径

两个 DVP 接收/状态监测/采集流水线 → 各自两个 DDR 帧槽 → 共享 burst 仲裁器 → 当前来源的显示读者 → RGB565 展开与可旁路增益 → 中文标题/按键提示 → HDMI-OUT。

两个来源独立持续运行；`display_selected` 仅代表显示读者的订阅，不控制摄像头配置、采集复位或输入 VS/DE。顶层只把当前来源的 `read_request` 交给显示读者。隐藏来源不预取显示行。

## 所有权规则

- 有效帧必须通过原始几何判定、全部写行完成以及写事务排空，才发布完成描述符。正在显示或待发布槽不允许被写事务覆盖。
- 显示来源在像素帧边界提交。DDR 域延后帧启动，使选源同步先稳定；锁定本帧 read_bank/display_id，不在 burst 中改源或改槽。
- 隐藏时禁止新显示行命令；已经开始的整行命令（内部包含多个 burst）继续返回给旧来源，直到最后有效拍及命令尾状态排空，才释放该读者占用。
- 释放读者时，若没有更新的 pending 完整帧，则把最后显示槽及 ID/时间转为 pending。这避免隐藏时间很短、下一帧尚未发布时重新选中却丢失全部完整帧描述符。
- 隐藏来源没有读者占用时，保留最新 pending 槽，使用另一个槽采集；新完整帧替换 pending，使旧 pending 槽可回收。重新选中时消费当时最新的完整描述符。
- 读超时或行欠载时输出保护黑色，保留未排空事务的槽；后续安全帧边界重新预取，绝不以另一来源填补。

未来前摄独立网络读者需要自己的占用/释放条件，并与相同槽生命周期合并。不得把未来读者的允许信号接到 KEY5，也不能把显示读者释放误当作所有读者都已释放；本轮未实现网络读者。

## 存储与显示

HMIC_S 当前配置为 28 位 DDR word 地址、BANK[27:25]+ROW[24:10]+COLUMN[9:0]。256bit 拍地址增加 8；source[24:23]、slot[22]、offset[21:0]。一行 1280 RGB565 对应 640 个 32bit word，完整 720 行占 460800 word。两路帧槽首地址依次为 0x0000000、0x0400000、0x0800000、0x0c00000，没有改变 DDR 原图格式。

显示仍为 800×480，中央 640×360 取原图偶数行列。周围设计黑边不变。增益只在显示支路，`min(255,c+floor(c/4))`；顶层参数 `DISPLAY_GAIN_ENABLE=0` 可恢复未增益的 RGB 展开，底层模块也有 bypass 输入。

## 按键提示

KEY1～6 均使用 20ms 消抖按下事件，长按只产生一次。系统域把提示编码放入带确认的 toggle mailbox，像素域收到后保持约 2 秒；新事件刷新计时。提示位于 x=548..787、y=12..27，不触及中央实景或左上角标题。KEY6=J19，仅提示“处理待接入”；停车键保持时，其他意图键显示准确的“停车优先请求未生效”。

数字验证与实际板上验收分开。特别是加密 DDR 控制器内部、颗粒/PHY、电气 IO 延迟和后摄延长线不由本轮 BFM 或内部 STA 证明。
