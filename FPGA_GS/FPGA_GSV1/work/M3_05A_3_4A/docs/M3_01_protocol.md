# M3-01 GSV3 / v1 协议与实现

默认板卡 MAC `02:00:47:53:56:31`、IPv4 `192.168.50.2`；电脑 `192.168.50.1`，双方 UDP 50000。配置集中在 `rtl/network/m3_net_core.v` 参数和电脑启动参数。静态 IPv4、普通 MTU1500，共用一套 MAC/ARP/IPv4/UDP；通过消息类型区分业务。不支持 DHCP、ICMP ping、IP 分片、巨帧或视频压缩解码。电脑先发 HELLO，板卡回应 ARP 请求并记录对端 MAC。

## 应用头

固定48字节，所有多字节头字段均为网络字节序。视频固定1280×720，RGB565 位段为 R[15:11]/G[10:5]/B[4:0]，每像素先发低字节，例如红色 `00 F8`、绿色 `E0 07`、蓝色 `1F 00`。

|偏移|字节|字段|
|---:|---:|---|
|0|4|magic `GSV3`|
|4|1|版本1|
|5|1|消息类型|
|6|1|来源：FRONT_RAW=0，VIDEO_IN=3|
|7|1|格式1 RGB565|
|8|4|会话号，非0|
|12|4|帧号|
|16|4|时间戳，毫秒|
|20|2|宽1280|
|22|2|高720|
|24|4|帧内字节偏移|
|28|2|像素载荷长度，视频固定1280、控制0|
|30|2|分片编号0～1439|
|32|2|分片总数，视频1440|
|34|2|保留 flags=0|
|36|4|按键事件号|
|40|4|判定序号|
|44|2|有效期，毫秒，1～2000|
|46|1|动作或判定码|
|47|1|原因或 HELLO 请求上传帧率|

每帧1,843,200字节、1440片；视频应用数据1328字节、UDP1336字节、IPv4包1356字节、以太网1370字节（不含FCS），满足MTU1500。头格式同步定义在 `tools/m3/protocol.py`。

|类型|数值|方向及行为|
|---|---:|---|
|HELLO/WELCOME|1/2|电脑请求/FPGA回应；HELLO reason=0/5/10/15/30请求上传帧率|
|HEARTBEAT|3|双向心跳|
|EVENT/EVENT_ACK|4/5|FPGA上报KEY1～4实际生效事件，电脑应答|
|RESULT/RESULT_ACK|6/7|电脑模拟判定，FPGA回应code=1接受、0拒绝|
|VIDEO_IN|16|电脑→FPGA，来源3右摄|
|FRONT_RAW|17|FPGA→电脑，来源0前摄原始彩色帧|

EVENT code1/2/3/4=左/右/直/停，绑定事件发生时最新前摄完整帧号。RESULT必须回传相同会话、事件和前摄帧号；sequence递增；code0/1/2=未知/允许/拒绝，reason0/1/2=无/红灯模拟/实线模拟。告警不修改本地意图灯，不传检测框。

## 有界恢复与时间

电脑每250ms发送HELLO和心跳；板卡心跳500ms、失联2000ms后反馈UNKNOWN。在线期间不接受其他会话抢占；重启工具后等待旧会话到期，新HELLO自动建会话。事件200ms重试，事件ACK停止事件重发；电脑RESULT也按200ms重试，FPGA相同/旧序号不重复执行。判定有效期从FPGA按键发生时刻计，不能通过重发延长到期时间。有效性仍绑定前摄，无论板上当前显示哪个视角。

VIDEO_IN同帧顺序组装；已经接收过的较早片忽略，缺片后收到更高片/乱序则丢弃组装，错误尺寸、格式、片号、偏移和长度拒绝。2秒未完成丢帧，下一较新完整帧自动恢复。全部片的DDR写事务结束后才发布，旧帧不倒退；最近完整右摄帧超过3秒转为无信号。帧号32位按有符号差比较处理回绕。

MAC先校验完整FCS，再交给协议核心。IPv4头校验、非零UDP校验和校验通过后才写DDR；IPv4允许UDP校验和0，板卡发送UDP校验和0、以太网仍生成FCS。接收4个2048字节槽，满则丢包，后续完整帧恢复，不无限排队。

上传只持有一个前摄完整描述符，按1280字节片暂存，整片到齐才交给MAC；主机慢时获取最新可用完整帧并跳过旧帧。断网先排空已经发出的DDR读事务，再释放网络读者，不能提前复用仍在返回的数据槽。

FRONT_RAW时间戳来自FPGA前摄帧起始的本地毫秒计数；VIDEO_IN时间戳为电脑进程启动后毫秒。两者没有时钟同步，不能相减当单向延迟。工具报告本机收帧率、完整/缺片/重复/事件/ACK/心跳统计；本版无实物吞吐测量。时间判定寄存分级带来最多约20ns观察延迟，相对毫秒期限可忽略。

## DDR和双读者

地址单位为32bit native word，一个256bit beat推进8。单帧占460800 native words（0x70800），不是每拍地址加1。

|来源/槽|native基址|字节基址|
|---|---|---|
|前0/0|0x0000000|0x00000000|
|前0/1|0x0400000|0x01000000|
|前0/2（仅前摄新增）|0x2000000|0x08000000|
|后1/0、1|0x0800000、0x0C00000|0x02000000、0x03000000|
|左2/0、1|0x1000000、0x1400000|0x04000000、0x05000000|
|右3/0、1|0x1800000、0x1C00000|0x06000000、0x07000000|

MES50HP手册2.2.3明确为两颗4Gbit DDR3，总8Gbit（1GiB）、32bit总线；前摄第三槽起始字节0x08000000、结束0x081C2000，在实际容量内。

前摄独立 `net_held/net_bank/net_id/net_time`，显示读者和网络读者可以持同槽或不同槽，写者排除两者持有槽。仅前摄扩三槽，其余输入保持双槽。五端口原生DDR仲裁：前三路各自写/显示读，右摄写/显示读，上传独立只读。显示增益、滤镜及文字全部位于DDR读出之后，上传不经过该链。

## PHY与边界

通用MES50HP网口1、RTL8211E；只适配千兆RGMII，必须手动确认电脑链路1Gbps。复用原厂网口1的RGMII串并转换和125MHz PLL相位配置，不启用网口2、不写MDIO延时寄存器、不叠加第二套软件延时。PHY上电复位约84ms；发送数据和转发时钟分别按各自PLL相位释放复位。

RXC F14，RXCTL F9，RXD H10/H11/G13/H13；TXC G16，TXCTL B18，TXD F17/D17/C18/A18；PHY复位B20。MDC A20/MDIO C19本版未实例化。RGMII与同bank的意图LED按原厂3.3V约束统一：旧LED1.2V与新网口3.3V曾实际触发VCCIO冲突，最小引脚工程确认后修改，LED逻辑含义未变。

125MHz网口时钟与DDR/显示域异步，通过有确认的槽邮箱、按键邮箱和状态邮箱跨域。工程STA覆盖内部时钟及复位路径；PHY引脚外部时序、电气、链路与实物误码仍须上板验证，不把内部STA等同于外部IO签核。
