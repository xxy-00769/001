- 对整体偏暗给出可验证的处理，必要时仅在显示端增加保守、饱和防溢出的轻量亮度调整，保留原图旁路，原始 DDR 图不变。

- 生成新版本位流，提供用户可直接执行的观察测试。

## 3. 优先排查路径：证据后修复

先用短表列出最有区分度的候选、检查与结果，不进行无边界审计。指挥侧已观察到：顶层两路 buffer 都接了同一个 `read_request/frame_sync`，未显示来源也持续读 DDR，最后才选 RGB。这是可优化的实际结构，但尚不能断言它就是串源根因。

优先检查：

1. **地址与来源隔离。** 沿实际 HMIC_S 地址单位/位宽核对 source、frame bank、行地址，直到实际 IP 映射，证明两路不重叠、不截断。测试内存模型必须保留相同地址含义，不能因模型使用理想完整地址掩盖硬件别名。
2. **burst 所有者与数据归属。** AW/AR 握手、第一数据拍、有效中间间隙、最后有效拍及 grant 释放都须按实际 HMIC_S 约定。特别核对现有仲裁器 ADDRESS→DATA 门控，是否会遗漏与地址接受相邻或同周期到达的合法 WREADY/RVALID；按手册允许时序验证，不能套标准完整 AXI 假设。读数据广播可以存在，但只有正确读者能接收有效拍。
3. **行缓存与截止时间。** 两路读请求竞争时的最坏服务间隔、行缓存覆盖/绕回、预取与读取速度、可用行计数跨时钟和 `output_bad` 触发条件。检查屏幕下部异常是否能被一次迟到或帧间状态残留解释。
4. **显示来源和帧槽。** KEY5 事件、selected_view、读源、帧槽和 OSD 对应；没有 KEY5 时整帧来源必须稳定。已有帧边界提交机制先检查，不要简单再加一层同步就宣称修好。
5. **输入与外部时序。** 根据证据检查 DVP 采样、帧尺寸/错误及延长线影响；不要把所有问题先归给排线，也不要用不完整 STA 的通过结论排除外部时序问题。

允许用单路采集/两路采集、单路读/两路读做内部对照；正式版恢复双路采集。连续两次同类尝试没有新证据，调整假设或检查，不能不断改参数盲试。发现明确根因后只修必要路径，再回到同一失败检查验证，不为获得漂亮测试数量无限加用例。

## 4. 显示读取结构要求

单视角模式优先改为“两个来源都采集，显示只读取当前选中来源”。若实现前发现另一方案更小且能证明满足隔离/时限，说明证据并采用，不机械重写所有缓存。

若改变读调度，必须完整处理：

- 在安全帧边界锁定本次显示 source/帧槽；发出到 DDR 的请求与返回期间保持其归属。
- 旧 burst 完整返回后才能释放其读者/复用相关资源；不能仅门控 `rd_en` 后忽略正在返回的数据。
- 新源预取和行计数重新对齐，没有有效帧时保留正确的等待/失效状态；不能显示另一来源充数。
- 隐藏来源停止显示读取后，其帧槽仍能正常回收和发布；旧显示占用不能锁死该来源。恢复显示时应读取最新完整帧。
- 保留未来前摄网络独立读者的接口含义；不能把采集允许信号绑定 KEY5。

不能把换三缓冲、提高 DDR 频率或降低分辨率直接当通用修复；如确需改变规格或架构，提供负载/时序证据及实际影响，不无依据改变已验证小屏时序。

## 5. 右上角按键提示：明确本轮行为

使用消抖后的按下事件。提示建议保持约 2 秒，新事件刷新；长按不重复触发，复位无提示。位置在右上角可读区域，文字不越出 800×480，不覆盖左上角视角标题，不改变视频数据。

提示内容：

| 按键 | 文案 |
| --- | --- |
| KEY1 | `KEY1 左转请求` |
| KEY2 | `KEY2 右转请求` |
| KEY3 | `KEY3 直行请求` |
| KEY4 | `KEY4 停车请求` |
| KEY5 | `KEY5 视角切换`，可附实际提交后的前/后目标 |
| KEY6 | `KEY6 处理待接入`，本轮保持原图，不假装已有滤镜 |

当前顶层只有 KEY1～5，KEY6 需对照 MES50HP 实际引脚表补接并检查约束，不能只在仿真里生成 KEY6 事件。KEY7/8 本轮不启用、不强行扩展功能。

按键事件和提示状态跨系统/像素时钟域时使用可靠事件交付和一致状态，不能把单周期事件或多位编码直接跨域。采用够用的小机制，不开发通用 UI。停车保持期间其他意图请求被忽略时，提示要准确表达“停车优先/请求未生效”，不能显示已执行左转而 LED 仍为停车。

## 6. 必要验证与交付

新增一个真正针对本次症状的联合检查：两路采用显著不同的像素编码，包含 source_id/frame_id/行列信息；连续多帧运行，不只分别完整读一帧。覆盖两路不同相位、突发回压/返回间隙、合法最早数据返回、随机时刻 KEY5、长时间不按键和隐藏路重新选中。

检查必须证明：无按键时不会出现另一源像素；显示帧 source 与标签一致；切换无上一源残留；末行正确；停止隐藏路显示读取后采集仍推进；异常保护次数能解释、恢复后不残留。对只存在于真实外部 IO 的疑点，明确仿真不能覆盖的边界。

按键提示检查至少覆盖 KEY1～6、保持/超时刷新、长按与停车优先。亮度调整如新增，检查黑白端点、颜色、饱和不回绕以及旁路。

按既有脚本完成必要构建、时序/资源与版本打包，保存旧版本。最终报告固定包含：

1. 确认的根因、证据；未确认的候选单独列出。
2. 修改文件与行为变化，为什么比上版能解决症状。
3. 实际验证结果；说明新增检查怎样覆盖上版漏掉的行为，不只列通过数量。
4. 新位流绝对路径、版本、生成时间，构建与时序/资源摘要。未上板明确写待上板。
5. 用户逐步测试：先固定前摄不按键观察，再后摄，分别遮挡/移动不同物体，反复 KEY5，KEY1～6 提示及 LED，观察圈出区域是否还有异常。由用户断电操作排线，不要求带电插拔。
6. 用户能直接看到的改进：固定视角不串源，原异常区域恢复正确内容，亮度处理如实说明，右上角显示键号和功能。

本轮目标是可验证的修复版交付，M2 等用户确认后再推进；Flash 固化继续延后。不要求完整重跑未受影响的其他算法，不因局部诊断无限扩大范围。若无法确定现场串源原因，必须如实报告，不能把优化后的猜测写成已修复的板上结论。
