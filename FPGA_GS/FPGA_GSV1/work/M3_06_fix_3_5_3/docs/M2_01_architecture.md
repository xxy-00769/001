# M2-01 2.0 实现边界

## 输入、缓存与DDR

CAM0=0前摄、CAM1=1后摄、HDMI-IN=2左摄；来源3保留右摄。仅提取通用MES50HP `06_hdmi_loop/src/ms7200_ctl.v`，用本工程已有iic_dri包装成独立RX配置，原MS7210不依赖输入是否连线。输入引脚来自同一通用板FDC，没有采用三HDMI专用底板引脚。

MS7200配置24bit SDR RGB888、外部HS/VS/DE。EDID改成单一首选1280×720p60 DTD，74.25MHz、总1650×750、正HS/VS；不声明YCbCr、HDR或扩展块。完整写入后按原厂序列开放DDC（000C=00、000A=04）并持续校准轮询。该路径的真实HPD/PC枚举仍待上板，没有新增未经资料确认的FPGA HPD引脚。首版要求电脑RGB8bit SDR；不支持HDCP、任意分辨率或自动CSC源格式识别。

`hdmi_input`寄存RGB888→RGB565、VS/DE，视频域检查1650×750总时序，50MHz域检查VS周期816666..850000拍（包括59.94/60Hz）。完整有效像素1280×720再由现有monitor与owner核对。断开/异常规格不发布不完整图；无有效信号显示状态文字。独立monitor/pipe/owner/wr_buf保证三路都持续采集，无空槽可丢整帧。

地址保持原分配：[27:25]=0、source[24:23]、slot[22]、word_offset[21:0]；32bit word地址、每256bit拍+8。一行640words、720行460800words，四来源各两槽不重叠。仲裁器扩成PORTS=3，读写各自轮询，一个native burst唯一owner，地址同拍首/末有效数据和实际间隙均保持旧修复。

每源保留received/good/bad（monitor）、published/rejected（owner）、dropped（video域）、read_fault以及output_underflow_count（像素域）。这是内部保留计数，不是已测板上帧率，也没有新建遥测UI；未来需要独立网络读者仍须添加独立pin生命周期。

## 残余闪动的小改动

只围绕两项：一行预取是否有足够截止时间、一次迟到怎样触发保护。屏幕行周期992/29.545454MHz=33.575µs。旧路径行起点才请求下一行，遇忙直接撤销本帧，output_bad保持到下一帧，因此一次迟到可放大成后半幅黑。

M2新增`m2_rd_buf`，以已消费行数为credit预取两行（刚开始消费一行时最多三条完整源行驻留）。8192像素环形RAM容量大于最大3840像素前视量；每行仍完整取1280像素。请求在真实line done、ready和owner允许时发起，地址保持到实际完成。没有超时猜测、放松frame owner或取消像素欠载保护。新计数记录每个输出帧首次欠载。

SOF跨域等待保持8个DDR周期，使帧边界提交的来源/缩放值稳定后才启动。旧整行即使跨视图切换也继续排空，包括后续native bursts，原帧槽到完整命令完成才释放。旧返回跨SOF时继续保护，不能当成新帧。

正常返回的有限间隙可测试；native协议不限制最长停顿，因此不存在无条件有限最坏服务时间保证。仿真测得的45µs裕量收益不是现场根因证明；超过裕量仍保护置黑，下帧恢复。

## 显示与处理

800×480输出不变，内容区(80,60)..(719,419)。单画面2倍抽样，源末点(1278,718)；田字格320×180、4倍抽样，末点(1276,716)。每路RAM读指针分别步进1或2个32bit word，均刚好消耗完整1280源像素的环形段。上半画面只消费前/后各自窗口，下半只消费左摄窗口；其他读者不广播rd_en。

KEY5四视图、KEY6五模式的系统域请求用有确认的bundled mailbox送像素域，帧边界提交。按键保留20ms消抖、长按单次和停车优先。提示约2秒，展示实际提交的来源或处理模式；停车拒绝仍保留实际键号。

共享链：RGB565→已有1.25倍饱和显示增益/保留旁路→`m2_processing`四级流水→中文OSD→输出寄存器。所有HS/VS/DE/image/坐标同样延迟四拍。DDR不写入处理结果。

- 灰度：Y=(77R+150G+29B+128)>>8。
- 均值：每颜色通道九点和整除9，常数7282乘法右移16在0..2295区间等价精确整除；因果窗口锚点为右下点。每个子窗首两行/列用当前原图，横向历史自然在两个边界点后刷新，竖向用全局列分开存储并用局部行有效性隔离。
- 二值：Y>=128为白，否则黑；THRESHOLD参数可配置。
- Cb=clip((32896−43R−85G+128B)>>8)，Cr=clip((32896+128R−107G−21B)>>8)。每个窗口分三栏分别以灰度展示Y、Cb、Cr，左上文字明确“三栏Y/Cb/Cr灰度”。

右下占位格没有第四路采集；它只显示“右摄待接入”。窗口文字和断流状态在处理之后叠加，不会被滤波污染。

## 验证范围

新HDMI采样时钟按74.25MHz真实声明，视频域内部路径受STA约束；仅独立时钟域之间用异步组分开，未对HDMI域内部路径加false_path。现有可用资料没有给出完整板级MS7200输出tCO/布线偏差，仍缺外部input/output delay；这是明确未签核项，不能用内部STA通过代替电气验收。沿用的DVP外部IO/no-clock限制也保留。

组合仿真用实际owner/原生控制器/三路仲裁与等容量同步行RAM，压缩为1280×32的多帧压力序列；输入第三路74.25MHz、两摄异步约42MHz。另用实际屏时序完整720行DDR地址与2/4倍抽样检查，并独立跑厂商DRM的4倍抽样。HDMI适配器用完整1650×750时序检查。仿真不包含加密DDR PHY、真实颗粒和PC。
