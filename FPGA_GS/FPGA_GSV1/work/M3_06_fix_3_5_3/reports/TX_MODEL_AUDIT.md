## 2. 原模型审核

原capture在真实TXC输出端口上建立生成时钟，2ns放在edge_shift中，`set_output_delay max=1/min=-1`。**在“内部采样点名义延后2ns，要求有效眼宽两侧各1ns”的假设下**，2ns只计算一次，未再放入output_delay；这套名义传播关系没有发现重复加2ns。它仍不是具有PHY内部PVT边界的外部签核模型。

8ns周期的generated clock waveform为{2,6}。当前IOCLK结构：setup使用同一源沿发出数据与TXC，hold检查下一源沿的数据；不是误用8ns完整周期代替4ns半周期。上升、下降捕获均有max/min约束，并保留clock_fall/add_delay。

PDS报告中CPR已包含在required time里：setup为正、hold为负。计算相位窗口直接使用最终slack，**不再手动重复加CPR**。源端共同路径的悲观移除不代表输出PAD是共同路径。

基线恒零三态TI仍产生TQ→PAD分析弧；这不能当成现场输出使能真实跳变。前轮固定OUTBUF去掉的是没有必要的三态结构。本轮没有通过false_path删除数据路径。现IOCLK报告不再含该TQ输出弧。

### 0.3ns与工具附加量

原root clock的0.2ns与capture的0.3ns没有在报告中简单累加成0.5ns。实际显示的uncertainty为0.350ns（基线capture=0.2时为0.250ns）。额外0.050ns的具体工具内部组成在当前用户指南中没有找到权威拆分，故只报告观测值，不命名为PCB公差、PHY公差或测得抖动。

不能把旧0.3ns整体留作“已证明板级预算”，也不能删它后称外部签核通过。特别是直接使用PHY RXC双沿时，表65的45%～55%占空比此前没有被完整覆盖：最短半周期为3.6ns，下一数据沿可提前0.4ns；同源同沿setup不受这项半周期缩短影响。对每一个捕获沿，另一个占空比极限会限制其hold，因此两种工况必须都覆盖。

本轮只修改TX约束：去掉无来源的对称0.3ns，以from/to限定 **setup=0.000ns、hold=0.400ns** 的占空比模型；真实1ns要求、实际传播路径、快慢角、CPR和RX约束均保留。这里setup=0只表示没有凭空新增setup预算，**不表示PHY/PCB不确定度为零或已经签核**。未知PHY/PCB项不能据此发布。修正后也不能通过hold，故这不是为通过而放宽约束。

## 3. 全部引脚/双沿的公共窗口

定义delta为相对当前名义TXC相位的附加后移（正值=更晚）。每条setup路径给出 `delta >= -setup_slack`，hold给出 `delta <= hold_slack`。上下界取所有五个引脚、快慢角、双采样沿的公共交集。

`scripts/tx_phase_window.py`解析了基线120条、当前80条相关完整max/min路径；生成20组“引脚×角落×捕获沿”的区间，每组同时含setup和hold。完整表见 `ioclk_phase_window.md/json`；所有40个最差检查的实际clock insertion/CPR见 `ioclk_clock_arrivals.md`。没有只选一个最差WNS替代其余引脚。

|模型/敏感性|delta下界ns|delta上界ns|宽度ns|结论|
|---|---:|---:|---:|---|
|3.5.2原BUFG/三态/.2预算|+0.357|-0.449|-0.806|无公共区间|
|现IOCLK/固定OUTBUF/.3预算|+0.179|-0.215|-0.394|无公共区间|
|现IOCLK恢复到.2预算的算术敏感性|+0.079|-0.115|-0.194|仍无公共区间|
|现IOCLK移去全部.3、只保留原报告工具项，50%占空比|-0.121|+0.085|+0.206|仅名义敏感性，不能签核|
|上一行再覆盖45%～55%占空比|-0.121|-0.315|-0.194|即使PHY名义2ns、PCB理想，也无区间|

敏感性表是以已布线路径延迟为基础的代数分析，**不是又一次整机STA结果**。单独PNR的更新模型检查另存，不与整机混淆。

限制路径：

- setup下界：slow、TXD0、下降沿捕获，原报告195行；data=10.975，required=10.796，slack=-0.179ns。
- hold上界：slow、TX_CTL、上升沿捕获，原报告1635行；data=9.743，required=9.958，slack=-0.215ns。
- 同一上升捕获沿本身也要求delta>=0.116且<=-0.215；下降沿要求>=0.179且<=-0.153。**单独调整两种捕获沿也不能解决原.3模型的眼宽缺口**。

原报告路径展开：

```
setup data =4+2.814(IOclock late)+.426(tco rise)+3.621(PAD rise)+.114=10.975
capture pin =6+2.426(IOclock early)+.259(tco fall)+2.980(PAD fall)+.116=11.781
required =11.781+.365(CPR)-.350(uncertainty)-1=10.796

hold next data =4+2.426+.259+2.980+.078=9.743
capture pin =2+2.699+.426+3.621+.116=8.862
required =8.862-.254(CPR)+.350+1=9.958
```

这里capture base中的6/2已经包括名义PHY2ns，clock insertion表列的传播值不再包括这2ns。

若暂只看50%名义窗口，PHY延时为 `[2-a,2+b]`，板上数据相对TXC飞行时间差为 `[Bmin,Bmax]`，另有残余抖动Js/Jh，则窗口变为：

```
lower = -0.121 + a + Bmax + Js
upper = +0.085 - b + Bmin - Jh
width = 0.206 - (a+b) - (Bmax-Bmin) - Js - Jh
```

名义中心delta=-0.018ns、对称剩余仅0.103ns。再计0.4ns短半周期就已经不成立。这个计算说明为什么取得规格会影响判断，也说明不能把这些未知项统一写成实测0.3ns。

## 4. 空闲PLL输出和最小结构试验

不是以PLL5/5直接否决。实际占用核查：

|PLL|实际频率关系|空闲输出判断|
|---|---|---|
|配置u_pll，现位于PLL_158_75|输出1=10MHz、2=25MHz，旧0无用户；3/4无负载|有空闲输出；原VCO1300/125不是整数分频，不能只接一根线得到125|
|像素PLL|1485/10=148.5MHz|有空闲端，但1485/125不是整数；本轮不动HDMI|
|两DDR PLL|固定DDR相位/频率及硬位置|没有修改DDR来为TX腾资源|
|网口1 PLL|由网口1RXC参考，有空闲端|不使用，避免端口1断链拖停端口2|

只在隔离夹具中把配置PLL重设为1GHz（50/5*100），保留10MHz和25MHz频率，同时生成125MHz。该频率在所读文档范围内；相位步长125ps，2ns可用16步表示。**生产PLL文件没有修改**，没有改变已验证输出。

### 试验A：全局125MHz ODDR数据＋PLL另一输出直接转发TXC

`tx_clock_probe`使用实际C20/F22/C22/E20/E22/F21、-6 Production模型、相同24mA FAST、两个捕获沿的1ns要求。2ns来自PLL输出相位，模型不再另加PHY2ns；这是拟配合关闭PHY TX内部延时的结构夹具，未修改生产PHY。

小规模PNR完成。准确125MHz捕获模型下，公共区间 `[+0.379,-0.121]ns`，宽度-0.500ns。**该结构没有扩大窗口，不集成、不做整机重建**。

夹具最初仅在CLKOUT4直通非时钟负载上写divide_by1，PDS没有推断出PLL125MHz而继承了root20ns。已明确增加该PLL输出的8ns/{2,6}生成时钟后重做夹具PNR。旧错误模型报告仅留作`initial_model_not_signoff.rtr`，没有用于结论。这也实证了不能只看RTL的PLL参数，必须核对实际Clock Summary。

### 试验B：空闲输出0的专用IOCLK＋CLKOUT0_EXT转发

`tx_ioclk_pll_probe`把配置PLL固定在整机现有的PLL_158_75，尝试用闲置输出0/WL提供专用IOCLK，并用EXT转发到C20；不增加PLL、不使用网口1参考。

第一种RCLK经IOCLKDIV/BUFG的映射报Place-0092。为区分是否仅分频输出导致失败，改用同一PLL独立62.5MHz输出提供RCLK，随后获得更明确结果：

```
The driver clock_pad/opit_1 ... CLKOUT0_EXT ... IOL_327_294,
PLL ... PLL_158_75, it is incompatible.
Place-2039: placement site ... incompatible.
Place-0084: IO_CLOCK ... fixed at PLL_158_75 is unreasonable.
```

工具建议`PAP_CLOCK_DEDICATED_ROUTE FALSE`，**没有采用**。这条具体固定位置/输出/引脚组合不是合法专用路由，不能把“PLL有空闲输出”直接等同于已具有可用专用发送时钟。没有扩大到搬动DDR、像素或网口1PLL。

### 试验C：250MHz单沿数据寄存器＋移相250MHz单沿二分频TXC

只在隔离夹具中使用配置PLL的两个空闲全局输出：CLKOUT3=250MHz相位0，CLKOUT4=250MHz相位2ns。数据每个250MHz上升沿变化；TXC在另一输出的每个上升沿翻转，得到125MHz。两个输出都能使用全局合法路由；实际六个PAD均映射为OREGIS。拟配合PHY关闭TX内部延时，避免再次叠加2ns；**未修改生产PLL、PHY、发送器或RX**。

这是与当前RXC双沿OSER4不同的结构：数据和TXC都只使用250MHz正沿，因此不能将RXC 45%～55%导致的0.4ns短半周期直接套入。通用窗口脚本输出里的`datasheet_duty_sensitivity`对于此夹具不适用，不能引用为此方案的否决证据。

`tx_sdr250_probe`完成真实PNR，原0.3ns压力模型得到名义区间 `[+0.170,-0.219]ns`，宽度-0.389ns。但检查完整路径发现**这个结果的捕获时钟模型尚不符合单沿二分频的边沿来源**：报告430行后的下降沿捕获从CLKOUT4的下降沿传播；物理RTL的`clk_ff <= ~clk_ff`只在CLKOUT4上升沿触发。不能仅因Clock Summary的8ns/{2,6}波形正确就称其捕获弧正确。

为区分是否只是`divide_by 2`缺少明确源沿，唯一改变生成时钟为`-edges {1 3 5}`，在`tx_sdr250_edge_probe`重新PNR（2026-10-22 17:43:37，北京时间）。结果仍将下降TXC沿向上游传播为下降CLKOUT4沿，区间数字也未变。两份完整报告和对应输入保留。另以PDS shell的`info commands`核对已暴露约束接口：没有`set_clock_sense`/`set_sense`，不能照搬其他EDA工具的命令并声称生效；原始输出保存在`clock_api.log`。**此试验不能作为正确外部模型下的方案通过或最终不可行结论**；没有将有问题的生成时钟模型用于发布，也没有继续全板构建。下一项是需要工具支持正确表示“两个TXC极性都由250MHz正沿触发”的转发时钟路径，不能靠改刷新率式标签或删路径解决。

两份夹具中，数据OREGIS的上升tco慢角为0.298ns；TXC二分频反馈保留fabric触发器及PAD侧寄存器，真实路径也完整包含。没有用理想clock端口直接代替TXC PAD。夹具没有MAC/弹性包桥，不能称生产功能修复。若后续模型/窗口可行才值得集成；独立晶振频率之间必须另做按包弹性CDC，当前连续八字桥不能原样跨异步晶振。

因此目前只证明此结构能合法放置、实际落入IO寄存器；未证明它满足所需外部窗口。PLL资料中的300ps p-p period/cycle jitter不等于两路输出独立各±150ps；精调±50ps条目明确写CLKOUT1，不能直接当作CLKOUT3/4相对相位误差保证来删除0.3ns预算。

## 5. 实施选择与验证范围

本轮选择：停止统一移相/驱动调参，保留既有IOCLK TX为隔离WIP，修正TX模型占空比缺口。方案A窗口没有改善；方案B具体路由不合法；方案C布线合法但生成时钟的源沿关系未被正确表达，不集成或把其时序报告当成签核。24mA仍只是现有WIP的已分析电气设置，**没有实物或合格STA证明其能修复CRC，不发布或推荐为修复**。

本轮实际新文件是窗口计算器、完整窗口/clock arrival表、模型说明和隔离结构/模型夹具；生产约束只改TX模型，生产RTL本轮未再改动。没有扩大诊断，没有重复运行未改的生产功能测试。当前没有实现经验证可行的新发送结构，不能将分析工作写成TX已经修复。

更新模型在 `production_io_model_probe` 中直接实例化生产 `m36_rgmii_interface.v`，复制实际网口2IO约束和修改后的TX约束，执行Production快慢角PNR/STA（30秒，2026-10-22 17:30:19北京时间完成）。结果：slow setup +0.121ns / hold -0.315ns，fast setup +0.318ns / hold -0.120ns，与上述从整机路径计算的窗口边界一致。此处是**真实单模块PNR/STA**，不是整机重建或合格整机STA；输出数据发生器只是保持真实IO路径活动，不能称ARP/视频业务测试。没有生成位流。

前轮生产发送路径检查的12个源文件重新核对SHA，仍全部一致，因此沿用而不重跑：ARP、连续控制包、前摄长包、真实MAC TX DRM、OSER4/OUTBUF引脚重组、首末字节/FCS/IFG已通过。该逻辑验证不替代本轮电气模型/STA。

## 6. 精确缺项与交付门槛

需要的不是重新量全板，而是以下受限规格：

1. **RTL8211E在page7/extA4/reg1C[13:11]=111时，以外部TXC引脚为参考的有效有符号TXD/TX_CTL setup/hold或等价接受相位区间（含PVT/抖动）**。若厂家只给内部TXDLY min/max，还需确认表65的1ns如何换算到此模式的引脚，避免把接口眼宽条件错当内部触发器参数重复使用。仅“typ2ns”不够。厂家若确认现1ns内部眼宽模型正确，则当前双沿结构在文档占空比范围内无公共窗口，不能靠移相修复；若提供不同有效约束，才能依法重新计算，而不是自行放松器件要求。
2. **实际MES50HP网口2五条TXD/CTL对TXC的最大/最小相对飞行时间差**，可由对应PCB走线长度/叠层报告给出，不要求用户装抓包工具或测所有信号。它直接进入上述Bmin/Bmax。当前所给原理图/引脚表不足以替代该参数。

3. **仅针对备选方案C的PDS模型问题**：如何在Production STA中把二分频输出的上升/下降两种转变均关联至PLL CLKOUT4上升沿，并保留实际OREGIS/PAD的各极性延时。显式`edges {1 3 5}`已验证未修正完整报告中的上游极性。若取得合法约束方式，先重做此小夹具，无须重测摄像头或全量构建；若还要用CLKOUT3/4的移相输出，则需对应相对相位误差界限，不能把CLKOUT1精度或单路period jitter直接移用。
