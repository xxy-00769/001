# M3-04 3.3 网口右摄吞吐修改

基线：用户确认3.2显示正常、真实视频进入右摄，但请求5fps时电脑约4.89、板端约2.58fps。保留3.2包，网口2/M4暂停。3.3没有烧录，板端性能由用户实测。

## 证据和修改

1. 生产MAC循环发布包槽，旧core按编号固定优先消费。真实MAC/FCS/DRM加DDR暂停形成四槽积压后，消费次序1→0→2→3，对应分片0→3→1→2；只写40拍，整帧丢弃1次，MAC溢出和协议bad均0。新core循环消费次序1→2→3→0，四片写160拍，drop/bad/overrun均0。见reports/M3_04_baseline和最终backlog检查。这是确认的设计错误，不能解释现场所有bad_packets。
2. 旧right_store在held+pending时拒绝新帧申请，core占住MAC槽等SOF，原所有权检查复现了该条件。60Hz最坏等待16.667ms，大于5fps下四包约0.556ms的容量。新右摄三槽保护显示持有、最新完整待显示、正在接收三个引用；失败组帧只能重用无引用槽，完整帧才替换pending，读者仍在SOF且旧命令排空后切换。20个SOF相位检查申请有界且不撞引用，未取消保护。
3. 旧每包全扫描和载荷二次读取均每字节两拍，仅字节处理至少约53us，超过15fps平均包间隔46.30us。现在同步RAM地址前瞻连续扫描，每拍一字节；扫描时暂存1280字节载荷至8块显式DRM，完整协议/校验/会话/片序验证后才发40个原生256bit单拍DDR写。保留最早首拍/迟到数据等待，不产生未经校验的DDR写，不改成不匹配的AXI突发。
4. 新增MAC计数安全握手快照、原因遥测kind8。统计格式/长度、校验、会话、视频规格拒绝，序号/重复、组帧超时/打断、申请/等待、DDR提交、发布和实际显示新帧。显示计数在受保护帧首次输出有效像素时增加，Gray跨域返回；隐藏或60Hz重复扫描不增加。发布流水编号避免新会话复用帧号漏计。
5. 电脑改为按实际发送起点排程，迟到不追赶突发；增加sendto间隔最小/P99/最大统计。这不是NIC线上间隔。工具以同一预热后约60秒窗口显示发送/发布/显示/前摄接收及原因增量，JSON完整保存。
6. 首次构建新增校验拒绝计数CE路径setup为−0.001ns，未发布。将格式/校验统计使能隔一拍后重新布线STA，不放宽时钟/约束。最终结果见交付报告。
7. 顺序FIFO恢复检查复现：PHY侧MAC单独复位后，旧ACK=0011、读指针2、MAC目标槽0，导致持续溢出。新增双方异步复位/各域同步释放；核心只重启RX队列、保留会话和事件编号，已接受DDR写保持数据直至排空，未接受AW不撤销。三个复位相位回归通过。电脑发现计数器回退就重启预热窗口，避免显示2^32错误增量，保留控制去重。

## 地址和保护

单位为32bit原生字；每256bit拍加8，每帧460800字、57600拍、1843200字节。

|来源|帧槽原生基址|
|---|---|
|前CAM0|0x0000000、0x0400000、0x2000000|
|后CAM1|0x0800000、0x0c00000|
|左HDMI|0x1000000、0x1400000|
|右网络|0x1800000、0x1c00000、0x2400000（新增）|

右摄bank在core/store/network均扩为2bit，第3槽显式映射，不走原1bit拼接。全部帧区不重叠，最高物理地址小于256MiB。CAM0双读者所有权不变。

未改摄像头/HDMI寄存器、DDR原始彩色图、滤镜算法、亮度、KEY/LED、停车优先和端点配置。输出仍148.5MHz、2200×1125、正HS/VS、VIC16。

## 检查边界

组合检查使用真实MAC→core→DDR→右摄所有权→生产高清行读/缩放/OSD，完整720行、125/100/148.5MHz时钟比例，并发其他三路完整采写、前摄第二读者上传、双向MAC和主机心跳；DDR和可见像素使用独立oracle。该短程检查结束早于板端500ms心跳/遥测周期，板端遥测发送及控制事件/重试另由core和单元检查覆盖，不声称组合检查实际发送过这两类包。

长跑将独立验证过的DRM包装换为同延迟事务模型；包RAM/缓存另以实际GTP原语检查。性能组合仿真采用同延迟处理旁路，实际位流启用完整处理。滤镜/HDMI回归复用3.2完全未变的消费源码哈希，不声称本次性能仿真遍历了所有滤镜。

最终四路BFM采用写burst前3us暂停、连续原生写请求、读返回合法间隙。探索夹具曾对历史摄像头wr_buf施加逐拍断续写请求和35us整总线停顿，出现未完成采集数据不符oracle；未把它当右摄PASS，也未据此盲改已验收采集链。独立MAC/core检查另覆盖75周期写数据等待及四槽积压。任意长DDR停顿和NIC线速长突发没有保证。

未确认现场1402个bad_packets的具体组成，未测PHY模拟电气、NIC线上突发、板端60秒帧率。软件回环和仿真均不代表板端稳定15/30fps达标；本机请求30时软件实际约28fps，未达到30。
