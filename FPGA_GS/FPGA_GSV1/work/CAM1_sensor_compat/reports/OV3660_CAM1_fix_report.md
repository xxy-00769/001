# CAM1 OV3660适配候选 3.5.6

本轮只适配物理CAM1/后摄，不是网口1右摄。基线为已实物通过前摄15fps质量验收的3.5.5 TXDET1发布source；不使用项目根目录19处历史差异，不继承3.4 WIP。新候选尚未下载、尚未验证实景画面。

## 真实型号与已确认问题

用户下载ID1后，从COM23/115200实际取得9条完整串口快照，全部W13=36603660、W14=00000007。即两次独立读取0x300A/0x300B均为0x3660，四次事务所有ACK为0、没有超时。原始证据为ID1_actual_uart.txt、解码为ID1_actual_decoded.json。这是实物OV3660识别，非排线字样或仿真输入推断。

现发布CAM1初始化却与CAM0相同，硬编码OV5640的357项表、没有ID核查，配置完成不检查ACK。这一型号/初始化不匹配已确认；不能据此排除所有电气或采样问题，也不声称全部花屏现象的唯一物理原因已经证明。CAM0原OV5640配置保持。

## 接口与资料边界

DOUBLE-DVP-OV5640-1113原理图表明板端使用DVP、24MHz独立振荡器和名义DVDD1.5V/AVDD2.8V/DOVDD2.8V，PWDN下拉，复位由原控制器提供。OV3660原厂v1.3资料支持DVP、RGB565及1280×720，时钟、电源芯片级范围包含这些名义值；SCCB实测正常说明现有电源、控制接口足以进行ID通信，但不是全部模组针脚、电源质量或数据IO兼容的完整证明。

未找到TY-OV3660-75MM-V2.0厂家模组针脚表。原厂参考24针与本板存在针脚差异，但不能把参考模组直接当作TY模组，不能断言用户模组不兼容。完整资料、板端针脚及这些未知边界见interface_audit.md。本轮不改接线、电源、两路共用FPGA时钟或复位，不归咎排线长度。

## 修改文件与行为

- rtl/capture/cam_ov3660_table.v：235项固定OV3660序列（233次写、两次等待），由scripts/generate_ov3660_table.py从归档来源生成，ov3660_table_manifest.json逐项记录出处。保留专用模拟/ISP默认值，使用16:9的1920×1080读出范围下采样到传感器直接输出1280×720；不使用低分辨率放大。
- rtl/capture/cam_ov3660_config.v：等待原上电复位完成，两次确认3660后才配置。软件复位等待100ms；配置期间保持standby，完成格式/时钟/窗口后才启流，再等待100ms并回读19项关键寄存器。ID不符、任何ACK/超时错误、关键回读不匹配均不置configured，不开放CAM1帧发布。失败锁存寄存器地址/错误码，硬件复位后完整重配。
- rtl/capture/cam_sccb_write16.v：CAM1专用开漏写事务，7位0x3C/总线写0x78，16位MSB优先寄存器地址；独立记录地址、高地址、低地址、数据四个ACK。读事务复用ID1已通过的cam_sccb_read16.v。
- rtl/capture/cam3660_dvp.v：CAM1独立的RGB565字节打包。HREF/VS边界清除半字节状态；八项元组FIFO将RGB、DE、VS一起交接到原有PCLK/2域，不依赖HREF首字节落在固定分频相位。奇数尾字节或FIFO溢出给关闭帧加错误；不填充、不裁边、不涂黑。
- rtl/board/fpga_gsv1_top.v：只有CAM1接上述专用配置/打包，使用对应RGB565顺序，不再套用CAM0的红蓝交换；CAM1字节错误并入既有帧所有权结果，完整几何检查与DDR发布保护保持。CAM0实例/采集/上传路径逐段比较一致。
- rtl/network/m3_network.v、m365_tx_observer.v：相对3.5.5仅透传/输出现有UART的四个被动CAM1状态字，没有改变网络收发、PHY、PLL、RGMII、MAC、协议或帧调度。相对ID1无新增网络逻辑。
- flow.tcl：实际工程引用新增CAM1文件。constraints/mes50hp.fdc字节不变。

## 时钟、极性、颜色和带宽

不改FPGA PLL或CAM0时钟。转接板24MHz XCLK经OV3660自身PLL：303A=00、303B=18、303C=12、303D=20；按图2-7，REFIN=12MHz（允许4~13.5MHz），VCO=288MHz（允许150~500MHz），PLLCLK=144MHz（不超过216MHz），SYSCLK=36MHz。3824=01、460C=22选手动PCLK分频1，计算字节PCLK=72MHz，像素域36MHz。原CAM1 84MHz输入/42MHz像素域约束比计算频率更严格，保持原值。

这组选择考虑了RGB565每像素两字节，PCLK/SYSCLK=2：1280列需要2560个字节时钟，小于HTS2172对应的4344个字节时钟；不是只给出PLL频率而忽略行输出带宽。HTS2172、VTS1322下理论帧率约12.54fps，实际需板测，可能受曝光等影响。本轮未承诺后摄30fps；前摄上传和网口右摄15fps配置不变。

4740=23按资料选择正PCLK/HREF/VS极性且PCLK不停门；FPGA沿用上升沿输入采样。501F=01、4300=61明确输出先{R[4:0],G[5:3]}后{G[2:0],B[4:0]}，CAM1直接形成标准RGB565。真实传感器PCLK频率、数据相对边沿、电缆/PCB偏斜尚未测量，不能以内部STA或理想仿真声称这些板级IO窗口已签核。

## 串口状态

沿用COM23/115200的N2 35O四十字格式，网络W0~11不改。

- W12=4F563336（OV36），与ID1的43414D31区别，避免旧解码误读。
- W13：两次实际ID。
- W14高16：最后配置/回读寄存器；中间8位错误码；低4位依次identified、ID finished、configured、failed。成功稳态通常30080007。
- 错误码1=ID不符，2=写NACK，3=总线超时，4=回读NACK，5=回读值不符。
- W15：高16几何异常帧数、低16几何正常帧数，均为低16位计数；它们是采集monitor结果，不是DDR发布数，奇数额外字节的独立错误不冒充几何计数。

复用原read_net2_diag.ps1采样，再用scripts/decode_cam1_ov3660.py解码；没有另建双击入口或大型诊断系统。

## 用户最短验收

只下载本包唯一3.5.6完整功能候选，沿用现有接线和程序，等待约2~3秒。先检查田字格右上“后摄”，应有完整、颜色正常的独立实景，没有绿紫花块、错行或重复拼块。若黑屏/花屏，保持现状，回复现象；开发端用现有串口一次读取ID、配置结果和几何计数，不要求换线、配IP或反复重启。

然后分别遮挡CAM0/CAM1，只有对应“前摄/后摄”窗口被遮挡；用KEY5检查后摄单画面及田字格，用KEY6简短切换确认滤镜正常；最后短暂看一下现有前摄上传和网口右摄是否维持原有表现。不重复网络60秒、算法或自动重连验收。
