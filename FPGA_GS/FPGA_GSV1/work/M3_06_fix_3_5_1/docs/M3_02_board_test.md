# M3-02 3.1 普通1080p显示器与真实视频联调

3.0已由用户看到四路与前摄上传；3.1的新显示规格、文件源和板端实际性能仍待上板。本轮未自动烧录、固化Flash、改网卡/路由/防火墙或安装依赖，3.0/2.1包保留。

## 接线与规格

- CAM0前摄、CAM1后摄保持原接线；电脑HDMI-OUT→板HDMI-IN（左摄），**板HDMI-OUT→普通1920×1080显示器**，不再用原800×480小屏。
- 电脑对板HDMI-IN继续使用独立扩展桌面，活动信号1280×720、60Hz、SDR/RGB8bit。工具放电脑主屏，左摄扩展屏播放不同内容。
- 网线仍接MES50HP**网口1**，确认1Gbps。电脑物理有线网卡手动设192.168.50.1/255.255.255.0，板卡192.168.50.2，直连无网关/DNS；不要改WLAN/虚拟网卡。本版不实现ping，使用ARP、心跳和图像判断。
- 本版交付输出**1920×1080逐行30Hz / 74.25MHz**。监视器信息页应显示1080p30。输入/DDR/网络仍是1280×720 RGB565；刷新率30Hz不等于网络源30fps。
- 单画面内容位于x=320..1599、y=180..899，1280×720像素1:1，周围黑边是设计边框。田字格填满1920×1080，每格960×540；最近邻采样源坐标为floor(4*x/3)、floor(4*y/3)，直接从720p原帧取样。

## 启动工具

依赖：Python3.9+、tkinter、Pillow和**已有FFmpeg**，不需要numpy/OpenCV/PyAV。开发机使用现成的FFmpeg8.1.1，没有复制安装软件。其他电脑请在命令指定其已有ffmpeg.exe；找不到解码器时工具会准确报错。

先在本机选择自己的视频文件；下面E:/videos/road.mp4是用户替换的文件路径，不代表项目附送道路素材。

```powershell
cd E:/zhoumian/FPGA/FPGA_GS/FPGA_GSV1
python -X utf8 tools/m3/console.py --bind 192.168.50.1 --board 192.168.50.2 --video "E:/videos/road.mp4" --loop --ffmpeg "E:/ruanjianji/FlyingMouse/FlyingMouse Format/resources/ffmpeg/ffmpeg.exe" --right-fps 5 --front-fps 5 --auto allow --stats m31_stats.json
```

如果FFmpeg已在PATH，省略`--ffmpeg`即可。不带`--video`则启动合成RIGHT动态图案；GUI“选择视频文件”可选自己的文件，“播放/暂停文件”控制文件时间线，“循环”变更会从头重启，“切换测试图案”保留对照源。真实视频不强行叠加RIGHT文字。文件经FFmpeg解码、等比例缩放补边、RGB565小端转换后发送，绝不是发送MP4压缩字节。

暂停文件时反复发送最后一张完整图以保持右摄连接，恢复继续原位置；“停止/恢复右摄发送”则真正停发，最多排空一帧在途和一帧有界队列。停止后右摄约3秒显示无信号。非循环EOF停止发送，选择文件可从头再播；循环模式自动继续。换源完成旧在途帧后使用新的完整帧身份，不混发半帧。

“前摄原尺寸1280×720”开关在原尺寸和适应窗口预览之间切换；小屏/系统缩放可能需要调整窗口。保存PNG始终为1280×720原始像素，不保存缩小预览。预览/保存与板上处理无关。

## 60秒实际板端统计

GUI与headless二选一，不能同时占用50000端口。先以5fps联调；确认正常后可手动改`--right-fps 15`，以实际完整帧率和板端计数为准。软件回环15请求只约13.31fps，绝不承诺板端15fps。

```powershell
python -X utf8 tools/m3/console.py --bind 192.168.50.1 --board 192.168.50.2 --video "E:/videos/road.mp4" --loop --ffmpeg "E:/ruanjianji/FlyingMouse/FlyingMouse Format/resources/ffmpeg/ffmpeg.exe" --right-fps 5 --front-fps 5 --auto allow --headless --seconds 60 --stats m31_board_60s.json
```

区分：`requested_right_fps`是请求值；`right_fps/right_frames_sent`是电脑实际完整发送；`board_right_published/board_publish_avg_fps`来自FPGA心跳快照；`board_right_dropped/board_drop_delta`为组装异常/超时整帧丢弃；`front_fps/front_frames`为电脑完整前摄接收。`missing_packets/incomplete_frames`是前摄接收缺片统计，不能替代右摄板端计数。短间隔`board_publish_fps`有0.5秒量化，验收用平均值/累计差值。退出时保存统计，回传命令、显示器信息页、图像与JSON。

## 后续端口分工

本轮网口1同时承载右摄、前摄和控制；配置集中在config/m3_endpoints.json，由构建脚本生成硬件端点常量。**最终网口1只负责右摄视频源及必要会话，网口2连接香橙派负责前摄和控制。** 下一轮分流时各自维护会话/失联状态，迁移现有一个网络读者，不复制前摄DDR读取；本轮没有启用网口2或真实识别，M4尚未开始。
