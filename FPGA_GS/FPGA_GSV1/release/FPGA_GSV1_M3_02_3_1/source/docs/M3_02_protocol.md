# M3-02 3.1 协议增量与端点配置

视频/控制包继续使用[原GSV3协议](M3_01_protocol.md)。1280×720、RGB565小端、每片1280像素字节、每帧1440片、48字节应用头均不变。FRONT_RAW仍只来自CAM0的独立完整原始彩色帧，不经过显示增益/滤镜/OSD。

本版板卡发送的HEARTBEAT增加flags bit0=1能力标记。仅当此标记存在时，frame_id为右摄完整发布累计数，offset为右摄组装丢帧累计数，sequence为bad_packets累计数；均32bit模回绕。缺片/异常导致的同一组装帧只算一次丢帧，多余尾片不重复计数。未开始组装的非法包由bad_packets表示，不冒充已发布帧。EVENT和RESULT的会话、唯一事件、帧身份、sequence和TTL语义不变。

电脑从首次能力心跳开始差分计数并以本机接收间隔计算平均板端发布帧率。500ms心跳间隔造成瞬时量化；短时读数不等于60秒平均值。发送、板端发布、前摄完整接收是三种指标。软件回环对端模拟的心跳不属于实物数据。

`config/m3_endpoints.json`集中记录MAC/IP/UDP及像素、控制业务归属，`scripts/configure_m31_endpoints.py`生成`rtl/network/m31_endpoints.vh`。构建脚本自动生成后冻结源码。本轮仍通过网口1/同一会话联调；修改JSON后须重新构建，工具不改系统网络。

最终架构：网口1右摄视频源及必要会话，网口2香橙派前摄/控制/判定。后续硬件集成需验证网口2实际引脚、时钟、PHY及延时，分开维护链路会话/失联状态，迁移现有单个网络读者。本版没有网口2硬件或独立双链路会话实现，没有真实识别。
