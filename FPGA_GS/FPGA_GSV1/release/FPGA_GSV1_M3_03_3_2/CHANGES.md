# M3-03 3.2 HDMI输出修复

本轮基于最终3.1源码，只修HDMI显示时钟及其受影响流水。网口2与M4暂停；3.0/3.1发布包保留。板卡没有自动烧录，显示器兼容性待用户验收。

## 确认的证据与尚未确认的原因

- Windows当前活动AOC2701设备名称为27B1。只读提取256字节EDID，两块校验和均为0；首选DTD为1920×1080、148.5MHz、2200×1125、60Hz。CTA含VIC16、不含VIC34；范围50～76Hz、30～83kHz。因此3.1的1080p30不属于这份EDID声明的工作范围，支持兼容性判断。
- 3.1最终源码实际配置是74.25MHz、2200×1125、VIC34，即1080p30；没有证据表明只是标签错误。不能凭电脑1080p60正常推断1080p30兼容。
- 3.1最终STA的像素关键路径为来源寄存→增益→色度，估计周期10.668ns，不能满足1080p60的6.734ns。首轮3.2增加增益及色彩流水后，新路由定位到滤波行DRM→两级垂直求和，setup约−0.721ns；据此增加DRM输出寄存，未重复盲换参数/种子。
- 板上真实PCLK频率、MS7210实际寄存器回读、HDMI接收锁定和电气裕量尚未测量。因此不能宣称刷新率是唯一根因，也不能把构建或仿真PASS写成27B1实测已解决。

## MS7210与输出采样核对

依据本地《MS7210 Register Map》DVIN/PA章节、《MS7210 Datasheet-CN》和原厂05_hdmi_test的148.5MHz例程核对，而非盲改初始化表：

- RGB24位SDR输入的1080p60需要148.5MHz；74.25MHz只适用于相应DDR输入方式，当前没有切DDR。
- 0x1202默认0：SDR、24bit444；0x1201默认0：R[23:16]/G[15:8]/B[7:0]；0x1200默认HS/VS/DE；0x1206默认不翻转DE/HS/VS。
- 保留原厂0x1281=0x04：PA采样时钟反相。FPGA最终RGB/同步均上升沿寄存，pix_clk由PLL直接输出；该设置将采样移向相反边沿。没有另加ODDR或随意改变相位。
- 0x00C0默认0：不使用8位SDR的除2或16位DDR的专用锁存时钟选择。生产初始化除参数化AVI外与原厂例程一致。
- AVI头82/02/0D，VIC16、checksum F6；数字检查另行验证整个包和为0。
- 未回读实体MS7210、未用示波器量板端时钟/数据/同步、外部IO延时尚未完整签核。内部STA不替代这些检查。

## 带宽与验证边界

四格每帧读取4×540行×80返回拍×32字节=5,529,600字节，60Hz为331.776MB/s；单画面110.592MB/s。源采集和上传仍720p，不把60Hz输出宣传成60fps采集。以四源各720p30及前摄上传5fps估算，原始DDR业务量约562.176MB/s；此为预算，非板端吞吐实测。

最终全尺寸生产读链仿真使用100MHz DDR/148.5MHz像素，保留合法返回间隙，仅在3/8 DDR拍提供显示读取服务，另5/8为其他业务留余量；四份完整720p快照独立来源/行列期望，检查完整1080单画面与四格、环回及切换。不将该BFM说成四个物理捕获/PHY的全顶层同时仿真。旧双读者/上传/控制/主机证据仅在消费源码hash一致时复用。

真实PLL检查使用生产封装与原厂GTP_PLL_E3模型，50MHz输入实际测其输出周期，再数完整输出帧。Icarus对原厂相位公式的浮点抵消负残差产生超长延时；仅在仿真副本将−1e−9ns到0之间的相位残差归零，比例/振荡器/锁定/分频逻辑均保留。综合生产文件不受此适配影响。该模型测量也不冒称板上PCLK实测。

工具、源采集、DDR帧所有权、上传和网络协议本轮没有重开发。文件右摄/播放暂停循环、CAM0原尺寸干净彩色上传、KEY/LED/停车优先、全部滤镜和中文继续保留。完整检查、资源和STA以本轮交付报告及冻结发布包为准。
