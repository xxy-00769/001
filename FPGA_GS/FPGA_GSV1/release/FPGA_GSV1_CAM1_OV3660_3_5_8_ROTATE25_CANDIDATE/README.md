# 3.5.8 CAM1旋转与原生720p提速候选

3.5.7已由用户确认后摄画面正常，继续作为当前可用回退基线。
本候选只适配CAM1倒装与帧率，不修改CAM0、HDMI、滤镜、按键、网络协议或
已验收的网口2PHY/PLL/RGMII实现。未自动下载或固化Flash。

## 改了什么

- `cam_ov3660_table.v / cam_ov3660_config.v`：传感器端同时水平、垂直翻转；
  3820=46、3821=06、4514=BB，保留其他配置位。顶层
  `CAM1_ROTATE_180=1`，以后正常安装可改为0并重建，无新增按键。
- CAM1原生1280×720 RGB565、无binning/放大。保持已通过的4740=20和PCLK采样。
  将之前1920×1080降采样读出改为中心原生720p，**视野会比3.5.7窄**。
- HTS2172→1800，VTS1322→800；相同SYSCLK36MHz下理论12.5375→25fps。
  PCLK仍为72MHz；不提高传感器PLL或修改任何FPGA PLL/时钟约束。
- 两种电源频率的曝光上限均796行=39.8ms；关闭夜间延帧和插帧，自动曝光/增益
  保留。日间可短曝光；暗处可能更暗、增益噪声更多，不能靠无限延长曝光保亮。
- CAM1增加独立第三帧槽0x2800000（DDR32位字地址），复用现有三槽所有权实现，
  只对CAM1允许VS消隐期接受下一次写授权。仍需下一VS的完整几何判定及全部720行
  DDR写完成才能发布，读者持有的帧不会被覆盖。
- `cam1_rate_status.v`和原串口预留字段：C1R8标识，分别输出完整采集、DDR发布、
  实际被选中且完整读出/未被健康保护遮黑的不同帧计数，并测量实际PCLK。
  其余网络数据通路不变。未把HDMI60Hz或重复旧帧当作新帧。
- `video_capture_status.v`仅CAM1启用已有字节错误的附加bit5，奇数字节/元组溢出
  不再被统计为完整有效好帧；其他来源的默认行为不变。

## 本轮定向验证

1. 真实SCCB线级事务：两次ID、246次ACK写入、45项关键回读；旋转参数0/1，
   方向配套值/曝光夜间位/几何回读错误和NACK拒绝ready，复位重配。
2. 真实时钟比例：字节72MHz→生产gearbox/CDC→像素36MHz→生产帧缓存、写控制、
   100MHz DDR事务模型和148.5MHz显示读取。六个完整720行输入帧；每个有效帧的
   独立帧号/行列像素检查，首末像素、双轴反向图案、三槽地址隔离、持续发布、
   坏行拒绝后恢复、隐藏后重新选择、原像素及960×540读取、合法DDR间隙。
   RAM使用既有容量/打包/一周期读延迟的行为模型；不是DDR器件电气仿真。
3. 被动统计：单bit分频CDC、PCLK停止/恢复、计数回绕、完整显示与重复帧区分、
   健康保护遮黑时不计为可见新帧。解码器以明确标记的合成串口样本检查，
   合成数据不属于硬件性能结果。
4. 全部保护文件、DDR地址范围和与3.5.7的差异清单核对；未重复摄像头0、
   HDMI、滤镜、网络协议、算法或历史全套测试。

实际日志、最终构建/STA、资源、生成时间及SHA256随本包提供。
构建通过不等于方向、曝光和真实≥20fps已实物验收。外部CAM1输入偏斜、
网络2PHY完整PVT/PCB签核仍不因本轮构建而变为已测。

## 最短上板步骤

1. 沿用现有接线。用户自行下载本包唯一`.sbit`，不写Flash。等待约3秒让配置和
   PCLK测量完成；原香橙派程序不改。
2. KEY5选择“后摄”单画面。在镜头前放四个可辨认标记A/B/C/D，处于新视野以内。
   相对3.5.7同一场景，应左上↔右下、右上↔左下同时互换；倒装后实景应正向。
   仅左右互换或仅上下互换表示失败。中文OSD应保持正向。
3. 保持后摄可见，双击`tools/cam1/CHECK_CAM1_10S.cmd`（COM23）。
   应收到C1R8、configured=true、error=0、720行、921600像素、geometry_errors=0；
   完整采集、DDR发布、可见新帧率均应≥20，通常接近25fps；坏帧不持续增加。
   PCLK应约72MHz，间接XCLK约24MHz。若无C1R8或时间不足，会明确显示采样未完成。
4. 短窗通过，保持同一后摄视图，双击`CHECK_CAM1_60S.cmd`。工具读62秒，以取得
   至少60秒的两个完整串口快照边界。应显示三类fps均≥20、坏帧增量0、几何正确。
   避免采样中切走后摄，否则可见新帧率会下降；这不是采集停止。
5. 画面持续观察应无错行、撕裂、绿紫花块。分别遮挡CAM0/CAM1确认来源独立，
   KEY5单画面/田字格中的后摄方向一致，KEY6滤镜正常，OSD正向。
6. 只简短抽查一次前摄上传和网口右摄仍约15fps；不重跑算法或整套历史验收。

日间及暗处各观察一次即可：暗处允许亮度/噪声变化，不允许靠延帧跌至20fps以下。
发现故障请回传本次`tools/cam1/reports/`最新JSON和TXT，以及方向/亮度现象。
若采集≥20但DDR/显示不足，不把它算作通过；若几何错误或坏帧增长，不关闭检查。

回退：下载保留的3.5.7位流，路径与SHA256见`baseline_acceptance.md`，无需改服务。
