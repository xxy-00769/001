## 2. A：先做一轮定向显示优化，不单独交付 M1-03

优先核对现有 `frame_buffer_owner` 的读忙判定与 `fram_buf` 的 `output_bad`：一次读行迟到是否导致本帧后续持续置黑。围绕读请求产生相位、行缓存可用裕量、返回完成跨时钟和帧开始复位做有区分度的检查。

允许有证据的小改动，例如提前预取、明确双行缓存所有权或修正完成判定边界；不能无证据关闭保护、延长任意超时、提高 DDR 频率、降低分辨率或用旧来源填补。先计算行截止时间和最坏服务间隔，再选必要改动；避免顺手重写全部显示系统。

## 3. B：电脑 HDMI 输入作为左摄

固定映射不变：CAM0 前、CAM1 后、HDMI-IN 左、网络右。前三路都持续采集，选择画面不启停输入。

电脑接线：电脑 HDMI-OUT → MES50HP HDMI-IN，MES50HP HDMI-OUT → MPI7001。Windows 使用扩展显示器，把本地视频播放器拖到该屏全屏播放。不得把电脑的 HDMI 输出接到板子的 HDMI-OUT。

首版优先固定支持 1280×720@60Hz、普通 SDR 无保护桌面/本地视频，不做自动适配全部输入规格或 HDCP。正确配置 MS7200，确认 HPD/EDID/时钟/同步、输出总线位序及 RGB/YCbCr 模式；以实际通用板资料为依据。若需限制 PC 输出规格，交付明确设置方法。

将 HDMI 有效像素整理成统一 RGB565，经独立 CDC、完整帧缓存接入来源 2。复用已有 owner 和数据格式；共享 DDR 仲裁扩展到三个真实来源，保持原生 HMIC_S 的所有权及首末有效拍修复。

HDMI 输入可以 60Hz，FPGA 缓存忙时按已有机制丢整帧；记录实际接收/发布速率，不为首版强制每个输入帧全保留而阻塞系统，也不能无统计宣称有效采集 60fps。输入断开/规格不支持时显示明确状态，前后摄继续工作。

## 4. C：KEY5 扩展视角和四宫格

KEY5 循环：前摄 → 后摄 → 左摄 → 田字格 → 前摄。

单画面继续使用 640×360 内容区，位于 800×480 小屏的 (80,60)，保持已有输出时序。田字格布局在同一内容区：左上前、右上后、左下左、右下右；每格 320×180，右摄格明确显示“右摄待接入”。不得把复制画面或测试图计作第四路真实输入。

单视角读取当前来源，田字格按窗口需要读取参与的来源。为窗口行提前准备数据，仲裁既保证显示时限，也不锁死采集写端；读返回遵守各自来源/帧槽/行缓存所有权。不要简单把三路 `rd_en` 全接到同一窗口请求然后在末端选择。

缩放先用整数最近邻：720p→640×360 为 2 倍抽样，720p→320×180 为 4 倍抽样。对源行步进、行缓存环回和首末像素做必要核对，不开发高阶缩放算法。

视角切换仍在帧边界提交；窗口有对应来源标签，断流只影响该来源。保持前后摄隐藏期间持续更新。

## 5. D：KEY6 一次接入基础处理

共享处理链，先实现：原图 → 灰度 → 3×3 均值去噪 → 二值化 → YCbCr 分量可视化 → 原图。

- 原图指处理链旁路，保留用户已确认的显示端增益；DDR 原始 RGB565 不变。
- 灰度/YCbCr 共用可复用的亮度计算，采用定点实现。去噪先一种滤波，不堆多个算法；二值化先固定且可配置的亮度阈值，不做本轮无关的道路自适应研究。
- 色彩空间模式必须明确标注分量调试方式，例如三栏分别显示 Y/Cb/Cr 灰度，不能把 YCbCr 数值直接作为正确 RGB 输出。
- 只处理当前显示图/窗口。滤波不能跨四宫格接缝；行缓存、边界和输出延迟按视图处理，不让相邻摄像头的像素进入同一个 3×3 窗口。
- 像素、DE/坐标、窗口来源和 OSD 对齐；文字在处理链之后叠加，不能被灰度/滤波污染。

KEY6 从“处理待接入”升级为真实模式切换。右上角显示键号及当前实际功能/处理模式，保持已有约 2 秒提示、长按不连跳。左上角保留来源/视图及当前处理状态，KEY1～4/LED 行为不变，停车优先提示不回退。

本轮不做道路语义、车道拟合、网络或全景，不增加多种滤波或复杂菜单。基础算法与参考图误差符合定点设计后就集成，不无限调参。
