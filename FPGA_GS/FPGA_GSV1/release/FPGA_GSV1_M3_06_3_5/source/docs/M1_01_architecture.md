# M1-01 双摄基础版接口与复用说明

## 实际数据通路

CAM0（板上旧名 cmos1）固定来源 0 FRONT；CAM1（cmos2）固定来源 1 REAR。
两路分别实例化摄像头配置、8→16 位转换、原始帧几何/断流监测、两级像素元组流水线、同一版本 `fram_buf` 和 `frame_buffer_owner`。不存在 CMOS 二选一宏。

两路同时持续观察 DVP。各来源使用独立的两帧 DDR 缓存，写端只接受获得空槽后的整帧，显示槽和待发布槽都禁止覆盖。忙时整帧丢弃，记入各 owner 的 `dropped_count`；格式错误/DDR 行完成数不符记入 `rejected_count`。沿用已验证的双缓冲所有权实现，当前不为了建议中的三缓冲重写成熟链路；吞吐受忙时丢帧影响，不承诺每个传感器帧都入存。

原始监测器在下一输入 VS 输出上一帧的行数/宽度检查结果。`capture_pipe` 将 VS、DE、RGB、帧号和时间一起延迟两拍，确保 owner 先收到上一帧 verdict，再看到下一 VS；这替代旧工程算法链提供的延迟，不启用任何图像算法。完整帧还必须等全部 720 个 DDR 行命令完成，且最后一拍确实返回，才可发布。

## 统一的来源、帧和读者约定

来源号统一为两位：0 FRONT、1 REAR、2 LEFT（预留）、3 RIGHT（预留）。当前只实例化前两路。

每个来源的描述符由 SOURCE_ID、`H_NUM/V_NUM`（1280/720）、固定 RGB565 格式、`pending_id/pending_time`、`pending/has_frame` 和读者的 `display_id/display_time` 构成。时间是独立参考时钟计数的毫秒采样；不是双摄曝光同步时间戳。状态监测还提供来源号、帧号、时间、像素数、行数和错误位的 256 位原子 mailbox。

DDR 地址为 HMIC_S 原有地址单位，保持旧行步长 640、整帧偏移字段 22 位：

```text
address[27:25] = 0
address[24:23] = source_id
address[22]    = slot
address[21:0]  = frame offset
```

不要将此地址直接当 CPU 字节地址；256 bit 一拍，地址每拍增加 8。每路、每槽分别占用独立区域。以后两个输入适配器可按同一 `fram_buf` 参数和调度端口加入，不需要变更已用来源号或布局。

读者 0 为显示：每个 `output_sof` 获取一个已完成帧并持有到下一安全 SOF；尚有 DDR 命令未结束时保留原槽，禁止释放并将该输出帧置黑。`read_request/read_ready/read_done`、槽号和已提交帧号是当前读者接口。两路显示读取都运行，使隐藏视角同样持续更新，KEY5 不参与采集、发布或 DDR 仲裁。

未来读者 1 为 FRONT_RAW 上传，要求沿用获取/持有/释放所有权，不能直接读取或覆盖写槽。本轮没有实例化网口读者，也没有实现第二读者的槽引用计数、仲裁或锁定；接入 M3 时必须在此 owner 上补充第二读者锁定并检查双读者占用，而不能把当前显示的持有标志当成网络持有标志。本轮提供统一来源/读者约定与必要接口边界，没有宣称双读者功能已经实现。

## DDR 与显示

`dual_ddr_arbiter` 对两个本地 HMIC_S 写端口和两个读端口分别按 burst 轮询；各方向只保留一个未完成 burst，避免响应串源。写数据由控制器 `WREADY` 请求，`WLAST` 是来自 DDR 的输出，不添加不存在的标准 AXI W/B 背压语义。读仲裁直到 `RVALID && RLAST` 才释放，允许末拍前存在间隙。

HDMI 使用 MPI7001 已有 29.545454 MHz / 800×480 / 约 59.927 Hz 时序。DDR 原图保持 1280×720，显示取偶数行、偶数列为 640×360，放在屏幕 (80,60)；黑边保留。左上角 (12,12) 用固定 16×16 宋体点阵显示黄色“前摄/后摄”，原始 DDR 图不含文字。

KEY5 在 50 MHz 域以 20 ms 消抖，每次稳定按下只发一次事件；请求经两拍同步，在显示 SOF 提交，标签和像素共用 `selected_view`。KEY1/2/3/4 对应互斥保持的 LED1/2/3/4（左/右/直/停），复位停车，停车键保持期间优先。

## 引脚和复用边界

KEY1..5 = K18/L15/J17/K16/J16；LED1..4 = B2/A2/B3/A3，按键低有效、LED 高有效。依据 MES50HP 手册物理 33/34 页，与原厂 beep 例程 KEY 引脚一致。原先占用 LED1..4 的 HDMI/摄像头/DDR 配置状态改为内部信号，避免争用；本轮不定义其他 LED。

`vendor/reuse_manifest.json` 逐文件记录旧工程绝对路径和复制时 SHA256。只提取三个现成 IP（HMIC_S 1.4、读写行缓存 1.6）及必要配置/时钟/控制 RTL；未复制旧算法、网口、HDMI-IN、工具输出或历史位流，未重新生成 IP。原厂/旧工程文件保留其头部和许可来源，没有补造独立开源许可。

本地修改仅包括：`fram_buf` 来源地址；owner 丢帧计数；MPI7001 时序输出对齐坐标。其余差异以当前文件对 manifest 原件为准。新板级顶层从旧顶层的摄像头、PLL、DDR 连接提取，不保留旧单摄宏、图像算法、KEY8 视效或 V5.2 显示增益。

## 验证边界

`scripts/check.ps1` 使用现有 Icarus 和厂商行缓存/DRM 原语。为规避 Icarus 对生成 IP 的常量 CS、byte-enable 和初始地址组合逻辑的 `always @*` 初值触发差异，仅在仿真输出目录把生成 IP 的组合块改成 `always_comb`，正式 IP 不变。该差异曾使首个 256 位字为 X，后续字正确；组合块初值适配后，首字预取和输入模式一致，没有为此修改正式写缓存 RTL。

双输入检查分为 8 行的故障/所有权用例及 720 行的完整帧用例；使用相同正式控制与厂商存储原语。前者包含异相位/速率、坏帧拒绝、读者占用、忙时丢帧和恢复，后者检查两路所有原始写入像素（包括第 719 行）、完整缩小输出及末拍前停顿。DDR PHY、摄像头电气接口、HDMI 实物不由该模型验证。

`scripts/build.ps1` 固定 PDS 2022.2-SP6.4，快照正式输入并记录哈希，执行综合、映射、布局布线、时序及位流。只有工具无错误、生成新文件、已有时序约束通过、源输入未改变时才标为 BuildPass。旧 FDC 的外部 IO delay 不完整、异步组例外和厂商时钟告警仍需如实记录，不能把内部 STA 通过等同整板 IO/CDC 签核。
