## 一、确认的问题与现场根因边界

| 类别 | 证据与结论 |
| --- | --- |
| 上版 RTL 接口边界缺陷 | ADDRESS 状态不转发数据，地址接受同周期的 WREADY/RVALID 被遗漏；`reports/M1_02_arbiter_before.log` 可复现。已修正为地址握手同拍或 DATA 状态均向唯一 owner 转发，首末同拍也可释放。手册未规定最小首拍延迟；尚无证据证明板上 IP 触发过此边界。 |
| 本轮单源读改造的缺陷 | 快速重新选中隐藏源时，原显示占用释放、下一完整帧尚未发布，导致唯一完成帧描述符丢失。厂商 RAM 和行为 RAM 都在第 26 帧复现置黑；跟踪显示 ready=11、busy=00、pending=00、reader=00、fault=0，排除了 DDR 繁忙/欠载作为这个失败的解释。释放时保留最后完整槽为 pending，新完整帧再替换；相同失败点及后续切换/恢复均通过。 |
| 隐藏槽回收 | 旧 owner 要等待 pending 被显示消费才能继续；仅门控 rd_en 会锁死隐藏源。现改为隐藏源保留最新完整槽，另一个槽持续采集，停止读取不停止摄像头。 |
| 已检查的候选 | 实际 IP 参数为 28 位、BANK+ROW+COLUMN、3+15+10，32bit word 地址、256bit 拍 +8；两路及四路预留地址不重叠。正常联合检查未出现行欠载或串源。不能据此宣称加密控制器内部或真实 DDR/IO 已验证。 |
| 尚未确认 | M1-01 用户现场“无按键闪现另一摄像头”的唯一根因，以及照片图内下方异常究竟由哪条真实链路触发，仍未唯一确认。没有把双路读负载直接认定为带宽超限，也没有把排线、曝光或外部 IO 当作已证实原因。 |

详细候选表、失败与修正路径见 `reports/M1_02_diagnosis.md`。本轮没有用固定图、关闭隐藏摄像头或覆盖异常区域交付。

## 二、关键修改与当前行为

- `rtl/frame/dual_ddr_arbiter.v`：唯一 burst owner 保持到最后有效拍；接受地址同拍的首/末有效数据；有间隙时不提前释放，不把广播数据的 valid 交给另一源。
- `rtl/board/fpga_gsv1_top.v`、`rtl/reuse/fram_buf.v`、`frame_buffer_owner.v`、`rd_buf.v`：双摄持续采集，单视角只发当前来源的新显示行请求；旧整行命令（多个 burst）继续排空才释放旧槽。新源在安全帧边界消费最新完整描述符并重新预取。像素来源提交到 DDR 帧启动之间按 29.545MHz/100MHz 的边界保留足够同步等待。
- `rtl/board/m1_keys.v`、`rtl/display/m1_hint_cdc.v`、`m1_key_osd.v`：六键 20ms 消抖事件、长按不连发；带确认 mailbox 向像素域交付提示，右上角约 2 秒，新事件刷新。停车保持期间被忽略的意图请求显示对应键号及“停车优先请求未生效”。KEY6 已接实际 J19，仅提示“处理待接入”。
- `rtl/display/m1_display_gain.v`：显示端逐色饱和 1.25 倍增益，原始 DDR RGB565 不变。模块 bypass 与顶层 `DISPLAY_GAIN_ENABLE=0` 保留原图旁路；KEY6 不绑定滤镜或增益切换。
- `constraints/mes50hp.fdc`、`flow.tcl`、`scripts/`：加入 KEY6 和必要新模块；新版本独立快照、构建与打包，旧发布包保留。新 PDS 使用独立文件名，不覆盖用户打开的旧根工程。

显示规格不变：800×480，640×360 实景位于 x=80..719、y=60..419，保留设计黑边。`output_bad` 故障保护黑色与设计黑边/场景阴影分开；没有遮挡图内下部。无 HDMI-IN、网口、滤镜、四宫格、全景、道路算法或 Flash 固化。

所有权说明见 `docs/M1_02_display_ownership.md`。已实现和数字检查通过不等于用户上板验收。

**已实现：** 上述双摄采集/单源显示读取、帧槽回收、显示增益和六键提示已接入顶层。**构建通过：** 综合、映射、布局布线、已有约束 STA 和新 SBIT 均通过。**待上板：** 固定视角是否仍串源、照片图内下部是否恢复、亮度/颜色和真实六键/LED/延长排线的验收；无板上已解决结论。
