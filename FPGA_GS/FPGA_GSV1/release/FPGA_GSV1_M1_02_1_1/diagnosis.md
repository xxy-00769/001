# M1-02 定向诊断记录

本表先于 RTL 修改建立。现场因果关系需上板确认，照片不是根因证据。

| 候选 | 有区分度的检查 | 当前证据 / 结论 |
| --- | --- | --- |
| DDR 来源地址别名 | 核对实际 DDR3_50H 参数、HMIC_S 地址映射与颗粒容量；模型按物理 bank/row/column 编址 | 当前 IP 为 28 位、BANK+ROW+COLUMN，3+15+10；每 256bit 拍地址 +8。source[24:23]、slot[22] 都落在有效 row 位，不是字节地址；控制器内部是加密 RTL，未作颗粒级验证。 |
| 首拍丢失 / burst 归属 | 在地址握手周期、紧邻下一周期、带间隙的首末拍分别计数 | 旧仲裁器仅 DATA 状态转发，ADDRESS 握手同拍返回会被丢弃；尚不能证明实物 IP 会在该周期返回。新增定向复现。 |
| 行缓存欠载或覆盖 | 多帧、完整行宽、环形地址绕回、末行、延迟返回与故障恢复检查 | 上版只验证两路各一帧，未覆盖选择调度和长时间并发；需要本轮联合用例。 |
| 隐藏路读者占用 | 停止隐藏路读请求后观察发布计数和帧槽 | 旧 WAIT_BANK 必须等待 pending 被显示消费；直接门控 rd_en 会令隐藏路停在 pending，必须同时修改读者释放和最新完整帧替换。 |
| 无按键来源切换 | 使用真实 m1_view_select、共享输出时钟、两路编码图与随机请求 | 原逻辑已有帧边界提交；不能仅凭双路读取就认定串源根因。 |
| 暗场 / 留黑 / 错误置黑 | 明确显示窗口、保护触发计数，独立验证显示增益 | 640×360 图位于 (80,60)，外围是设计黑边；图内错误与整体亮度分开处理。 |
| 外部 DVP/排线与 IO 时序 | 用户上板遮挡、固定视角、后摄延长线观察 | 未测；现有外部 IO 延迟约束不完整，不能用内部 STA 排除。 |

手册只描述地址和数据通道独立、数据有效时同步传输，没有规定最小首拍延迟。测试同拍是接口边界强化；不得把该测试失败直接写为已确认现场根因。

## 实际复现及修正

1. 上版仲裁器同拍首数据有效检查失败：`M1_02_arbiter_before.log` 中 `EARLY_BEAT_LOST ... write=00 read=00`。修改后同拍、相邻拍、间隙拍及两来源均通过。手册未给出最小延迟，实物是否触发此边界未知。
2. 本轮单源读取改造的第 26 个输出帧，在快速重选后摄时首像素置黑。厂商 RAM 与行为 RAM 都复现同一症状。增加 SOF 同步等待后仍失败，排除“只需延后预取”作为此失败的解释。
3. `M1_02_joint_trace.log` 给出区分证据：新源 `selected=1, sync=10, enabled=00, request=00, ready=11, busy=00, pending=00, reader=00`，故障计数为 0。这是完整帧描述符被释放丢失，既不是 DDR 忙碌，也不是数据到达过慢。释放旧读者时，若无更新 pending，则把最后显示完成槽转为 pending，后续新发布帧原子替换。
4. 同一路径修正后 `M1_02_joint_recovery.log` 连续 39 帧、199680 像素、15 次随机切换通过；两路各发布 13 帧。两次故意跨帧延迟触发前路保护计数 2，5120 个保护像素全黑，之后恢复正确图像；正常阶段故障计数为 0。

第 2～4 项是本轮新调度的实现验证，不冒充 M1-01 现场根因。现场“闪现另一摄像头”尚未在数字仿真中复现；电气、排线、真实 DDR PHY 和按键输入需要用户上板验证。原始双路读取结构只作为负载优化依据，未证明带宽超限。

## 明确的设计边界

- 保留 800×480 时序，640×360 实景位于 x=80..719、y=60..419；周围设计黑边不变，没有遮住用户圈出的图内区域。
- 灰码可用行计数、输出行数和 `output_bad` 继续检测欠载；无有效帧输出黑色，不以另一来源补齐。
- 单来源两个帧槽；隐藏路保留最新完整槽，另一个槽继续写入；新写帧完整结束且 DDR 写事务排空才可发布。停止读取不等于停止采集。
- 显示增益为逐色 `min(255,c+floor(c/4))`，黑白端点不变；模块 bypass 与顶层 `DISPLAY_GAIN_ENABLE=0` 保留原图路径。没有修改传感器曝光或 DDR 原始 RGB565。
- 本轮探索性仿真取消/失败记录不作为通过证据；最终正式检查及构建以新发布 manifest 为准。
