# M4-04-r1 人车检测录像演示

已部署、运行并通过SSH转发查看真实录像。FPGA保持断电，本轮没有启动LIVE_FRONT、绑定业务UDP或修改网络。四原片SHA256与M4-03清单一致，未重复上传或改写。

## 一键使用

全部电脑入口在 `E:/zhoumian/FPGA/FPGA_GS/FPGA_GSV1/orangepi/oneclick/`：

1. 双击 **启动智驾录像演示.cmd**。集中配置 `config.json` 的SSH地址已为192.168.0.4，用户名orangepi、22端口、远端根目录保持原值。当前密钥认证可用；如需密码，在SSH终端输入，不保存密码。本模式不需要sudo。
2. 自动打开 http://127.0.0.1:18080/ 。点击 **日间人车54秒** 可见路口行人、骑行者和车辆；**夜间车流18秒** 看夜间车流。定位按钮只跳转视频，不提供检测答案。
3. 下拉菜单可选四片，支持播放/暂停、循环、时间轴跳转、640或1280宽。画内显示中文类别、模型置信度和目标数量；“·续”及虚线框表示短时光流延续，JSON记录来源、检测帧和显示帧。分数不是准确率。
4. **保存原图及叠加** 将原生分辨率原图、预览叠加JPEG和同帧JSON分别写到远端 `m404/evidence/runtime/`。
5. 双击 **停止智驾录像演示.cmd** 正常退出服务并清理本入口的SSH转发。关闭启动窗口或浏览器后，远端继续运行，必须用停止入口停止。
6. 双击 **回退M4-03录像演示.cmd**：按PID/命令行核实并停止当前演示，选择原版M4-03后启动；**切回M4-04人车检测.cmd** 可恢复检测版。已实际测试M4-03启动及切回M4-04。两者都不自动启动LIVE。

远端项目根：`/home/orangepi/fpga_gs_m401_v0_1_2_20261021`；新程序在 `m404/`，生产解释器 `.venv404/bin/python`，控制台日志 `m404/state/demo.console.log`。HTTP仅监听127.0.0.1:8080，经SSH映射到电脑18080。原 `m403/` 与LIVE接收、重连、协议等共22个文件哈希未变。

备份：本地及远端 `m404/backup/m403_before_m404.tgz`；电脑启动器及原配置另存于本地 `m404/backup/`。四视频与场景配置继续保留原位。

## 实际模型与实现

- YOLOv8n COCO，640×640 RGB letterbox输入，INT8 w8a8。RKNN权重来自 `RKNNAI/RK3588-CNN-yolov8n`，固定修订 `5d57505a54edb67997caef03a5273c61081ca6ed`；来源声明为airockchip/ultralytics_yolov8。权重AGPL-3.0；Rockchip参考后处理Apache-2.0；SDK使用其自带许可证。完整类别、来源、SHA256、许可证在 `model_manifest.json` 与 `models/`。
- **实际后端RKNN/NPU**。系统librknnrt **2.3.0**、驱动 **0.9.8**；独立环境rknn-toolkit-lite2 Python API **2.5.0**，模型内嵌编译器2.3.3b3。发布卡推荐runtime2.4.0，但现有2.3.0已通过同帧对照和完整播放。本轮没有替换系统运行库/驱动。下载的较新librknnrt未安装、未加载；`release_validation.json` 保存实际进程映射。
- 生产环境继承已有OpenCV4.5.4、NumPy1.21.5、Pillow9.0.1和psutil5.9.0，新增API及ruamel.yaml0.18.6只放`.venv404`。ONNX Runtime1.20.1仅用于CPU对照。原`.venv`未改。
- 显示真实COCO类：行人、汽车、货车、客车、自行车、摩托车。不细分电动车，不支持锥桶、施工围栏，不输出“通用障碍物”。阈值0.25、同类NMS IoU0.45。
- 一个进行中的推理加一个可覆盖的最新帧槽；解码/驾驶叠加/预览不等待NPU。跟踪有短期上限并区分来源，切片/跳转/循环立即清除旧检测。原生原图不缩小；仅模型输入缩放，框还原到原图后再映射预览。
- 车道、灯色、驾驶规则仍使用原M4-03；本轮没有新增自动刹车或通用灯组/车道理解。新增框不控制模拟车辆。保留箭头、停车和告警，调整其位置及标签避让。
- 修复新性能历史清空后状态JSON短暂出现NaN的问题；暂停后检测fps会降为0。

## 效果、失败与验证边界

- 六张真实图像的浮点ONNX与部署INT8对照，主要同类目标匹配框IoU约0.94–0.98。此数值只检查部署一致性，**不是检测准确率**。输入RGB、padding、坐标还原、类别选择与NMS均已核对。
- BT约0.5秒：路边货车、汽车、行人及骑行目标；约57–59秒：近处行人/骑行者、交叉车辆、部分遮挡和远近目标。YJ夜间：前方车流、侧向车辆和少量行人。BT2/YJ2以车辆为主，不宣称两段覆盖了清晰行人和所有六类。
- 明显失败：BT 57.333秒车头盖被误报汽车（CPU0.45、NPU0.33）；YJ 98.000秒运动模糊骑行者被汽车框覆盖，部分前方眩光车辆漏检；低分远目标量化后跌出阈值。自行车/摩托车可能混淆，客车/货车的低分结果仍需人工核查。
- 原图2558宽缩到640，远处小人/骑行者只剩数像素；没有训练集或人工完整真值，未编造准确率。
- 下一步先针对夜间两轮车、远小目标与车头盖误检建立独立片段评估；可评估道路ROI补充推理和更合适的量化校准。确认部署差异之外的失败后，再决定小规模微调；本轮没有训练。
- 本轮通过4项目标检测定向检查：RGB/padding、无目标输出、不支持类别不冒充人车、epoch清理；浏览器通过暂停fps归零、四片切换、旧红灯强制告警及停车清除。重复启动复用同一PID；已实际安全停止、回退M4-03、切回检测版。未重跑FPGA/UDP或历史规则全套。
