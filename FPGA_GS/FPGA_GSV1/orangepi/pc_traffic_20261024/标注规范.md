# 交通灯标注规范 v0.1

日期：2026-10-24（Asia/Shanghai）。本规范用于人工复核；模型结果只是候选。`annotations/examples.json` 是首轮目视示例，尚非双人审定真值。

## 标注对象

- **灯体 body**：一件完整物理信号灯壳体，紧贴外壳，不包含立杆、支架、倒计时、背景和光晕。横排三孔共壳为一个 body；多个独立壳体即使在同一横杆上也分别标注。不得用一个大框包住整个路口。
- **灯组 group**：关系记录，用 `group_id` 连接有证据属于同一组件的 body；证据不足填 null。灯组不是默认训练框，更不代表本车控制方向。
- **灯面 lens**：能辨认的物理透镜/信号面，可包括未亮孔。与 body 通过 parent_id 关联。看不清孔的边界时不补画三个等分框。
- **发光区域 emitter**：当前亮起的可见发光部分；排除外溢光晕。严重饱和时只标可见区域并记录 glare，不从灯位推断颜色。箭头可用紧框或多边形；导出检测标签时不与 body 混用。
- **硬负样本 hard_negative**：尾灯、刹车灯、招牌、LED屏、倒计时、反光、红装饰物、路灯、道路指示牌，另记区域框及原因，不作为交通灯类别。整图负样本须检查全图确实没有漏标灯体。

## 属性及未知值

|字段|值及要求|
|---|---|
|kind|motor_vehicle / pedestrian / non_motor_vehicle / unknown；不能仅凭位置猜行人或机动车|
|layout|horizontal / vertical / single / irregular / unknown|
|state（每个可辨灯面）|red / yellow / green / off / unknown；共壳多灯可同时亮，保留每个灯面状态，不强制全壳单色|
|color_readable|true / false；false 时 state=unknown，必须给出原因|
|symbol|circle / arrow / pedestrian / other / unknown|
|arrow_direction|left / straight / right / u_turn / combinations / unknown；只有 symbol=arrow 且形状可辨时才填具体值|
|occlusion|none / partial / heavy / unknown，并尽可能记录可见比例；不臆测不可见边界|
|truncated|是否被图像边界截断；只框可见外壳，标 truncated=true|
|quality_flags|tiny / blur / glare / overexposure / compression / contamination / ambiguous_body 等可多选|
|unknown_reason|too_small / saturation / occluded / blur / mixed_emitters / cannot_identify_kind / other|
|control_relation|固定 unknown；控制方向属于后续空间推理|

`off` 只用于可清楚看见透镜且有充分图像证据未发光的灯面。漏检、黑块、遮挡、夜间欠曝和远小点均不能标 off。`redyellow` 应拆为两个灯面状态，不能映射成黄灯。S2TLD 的 wait on 暂不映射为任何确定灯色，保留源类别并人工复核。

原图可见外壳但远到颜色不可辨：保留 body，state=unknown，不加入可辨颜色准确率分母。原图连是不是信号灯都不确定：标 ignore region 和 ambiguous_body，既不作为确定正例也不当负例。必须分别记录 body 可辨、颜色可辨、箭头可辨；放大仅帮助观察，插值不能产生新证据。

## 工作流与质量门槛

1. 保留原始图片、源标签、许可证、下载版本、SHA256和尺寸。拒绝带推理框、叠字的截图进入训练；原有相机水印单列记录，不当类别线索。
2. 标注员先看整张原图找全部灯体，再看候选框。禁止只确认模型给出的框；尤其复查模型漏检的小灯、侧面灯、暗灯和行人灯。
3. 第一人逐图标注，第二人独立检查漏标、错标、框定义、颜色和箭头。争议交仲裁，无法达成一致就 unknown/ignore。`approved` 必须对应可追溯的人员/时间；AI目视首轮不能冒充双人签署。
4. 复核结果回写 review_status、reviewer、reviewed_at、decision。批次验收随机检查正例及负例，保存返工原因。全部400张通过检查才计入合格池；首批数量不代表可靠性。
5. 保留关系与属性的主格式为本目录 JSON 结构；以后可转换 CVAT/COCO。灯体检测仅导出 body，不把 emitter 框当作灯体真值。颜色/箭头只使用各自 readable=true 的子集。无法确认 kind 的确定灯体采用 ignore 或单独实验的通用灯体类，不偷偷并入机动车类。

初始建议训练类别为 motor_vehicle_body、pedestrian_body；非机动车/未知类别须先统计再决定是否增类。检测、颜色和箭头的训练入口分开，当前没有用伪标签直接训练的入口。
