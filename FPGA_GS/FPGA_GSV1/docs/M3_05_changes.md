# M3-05 3.4 修改范围与证据

本轮只处理HDMI左摄失效及后摄边缘绿点。当前为未发布候选；放行状态以最终报告为准。保留3.3用户确认的右摄15fps成果、1080p60、四来源、滤镜、中文、KEY/LED、停车优先及前摄干净原图上传。未烧录，现场恢复效果尚未确认。

## 已确认及未确认

- 3.2→3.3发布源码只改网络四个RTL。右摄第三槽0x2400000、前摄第三槽0x2000000均为32bit字地址，与后摄及HDMI两槽没有重叠；每帧占460800字，全部位于256MiB范围。未发现地址覆盖、来源路由或仲裁/帧保护错误，因此这些行为不改。
- 原摄像头PCLK与其÷2像素时钟被分到不同异步组，实际相关的字节打包→像素交接没有被STA检查。恢复相关检查后，首轮真实布线在后摄交接发现−5.503ns保持违例。这是明确的设计签核缺陷；不等于已证明实物每个绿点都由它引起。
- 原HDMI及摄像头无外部输入延迟预算。旧3.3 IO报告后摄最坏需约4.308ns保持，3.2约4.158ns；源码相同不能保证布局改变后外部采样相同。强制IO首级寄存器的首轮实现仍出现输入保持违例，未发布该实现。
- 数字仿真没有复现绿点或左摄黑屏。没有实物探针，**尚未确认现场HDMI第一个失败环节，也未确认两种现场症状的唯一根因**。本版用分阶段L码补上观察能力，不再统一显示“需720p60”。没有修改摄像头/MS7200寄存器、PLL相位、外部数据采样边沿、曝光或电脑设置。像素域内部÷2相位有明确修改及对应generated-clock约束。

## 实际修改

| 文件 | 行为 |
|---|---|
| `rtl/capture/hdmi_input.v` | RGB565、HS、VS、DE先统一IO寄存，再进入原尺寸/帧率检测及采集；完整tuple延迟由1拍变2拍。新增时钟活动和分阶段诊断。 |
| `rtl/reuse/cmos_8_16bit.v` | 保留原字节打包，改用同一字节时钟树下降沿的本地÷2触发器驱动像素全局时钟，使字节打包、VS与像素采样有明确半周期关系，避免原独立IOCLKDIV长插入路径。 |
| `rtl/board/fpga_gsv1_top.v` | 摄像头输入明确使用同组上升沿IO首级，保留原输入位序和采样逻辑。连接HDMI诊断并使用已有一致性mailbox跨域。原AXI调试标记和后摄调试标记保留。 |
| `rtl/reuse/fram_buf.v` | 仅导出发布toggle与显示读错误；去掉这四条新增端口/assign后，功能代码与3.3一致。 |
| `rtl/display/m31_video_output.v` | 仅传递状态码，像素/同步/增益/滤镜/覆盖流水未变。 |
| `rtl/display/m31_osd.v` | HDMI异常区域显示L0～L7。字形复用现有2拍OSD延迟，采用有限宽度行/列译码，避免动态宽位索引。正常画面不加诊断覆盖。 |
| `constraints/mes50hp.fdc` | 摄像头PCLK及其÷2时钟归入同组，恢复相关STA；补充外部像素输入预算。 |

输入预算为额外工程假设：采样边沿前后各1ns的引脚稳定窗口（摄像头11.9ns周期：min1/max10.9；HDMI13.468013ns周期：min1/max12.468013）。**此预算不是器件手册保证，也不是板上示波器测量；不能把该假设下失败直接当成现场根因**。最终STA须在此预算下通过；电气余量和实际线缆影响仍需实物确认。未放宽1080p60时钟、恢复后的相关检查或输入预算来凑通过。

## 仅运行相关检查

- 摄像头：真实生产输入寄存及字节打包/分频模块，完整720行/921600像素、720个首末像素、交替奇偶行消隐相位，独立RGB565期望检查。
- HDMI：生产输入→监测→capture_pipe，完整1650×750/1280×720，60/59.94Hz、错误行总量及丢VS；检查整组RGB/DE/VS与后级延迟、完整帧判定。没有实际MS7200/HDMI电气仿真。
- 诊断：8种首失败状态、失时钟恢复、8种不同可见码，以及每拍改变坐标时的2拍像素/区域对齐。
- 源码范围：与冻结3.3比较144个未改文件；顶层除输入采样外的功能接线、帧缓存控制、显示处理流水做移除新增部分后的代码等价检查，地址区间检查无重叠。网络、DDR仲裁/所有权、滤镜和电脑工具复用已通过证据，不重跑软件回环及算法穷举。
- 修改后的真实综合、布局布线、各角STA及位流生成另见交付报告。中间失败结果保留作证据，不作为推荐下载文件。

未运行：板卡烧录、HDMI链路电气测量、实际绿点观察、本版板端fps复测。3.3用户实测短窗14.37/14.27/14.31/4.98fps分别为发送/发布/显示/前摄基线，不能冒充3.4新测量。

## 未采用的实现

强制IO寄存的首轮出现输入保持违例；fabric首级能修保持但造成输入建立违例。本地IO时钟+IMDDR先报跨区域Place-0086；按实际引脚拆区域后报Place-0028。最小单引脚P/N及显式输入buffer小工程都复现Place-0028，未归咎数据分组。区域时钟小工程虽可布局布线，输入setup仍负；一般IDDR使用本地IO时钟的小工程报Route-0008。这些候选均已撤回，未发布。当前只保留表中最小候选和严格检查，不能把实现尝试写成现场症状已修复。
